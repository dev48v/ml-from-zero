MachineLearningFromZero · Day 60

⏳ Survival analysis — the corner of statistics built for a problem every other model in this series quietly ignores: some of your rows have not finished happening yet. Every estimator so far assumed each row carried a complete answer. Linear regression (D1) needed a number, logistic regression (D2) needed a label, Poisson regression (D47) needed a count. But the question "how long until the event?" hands you a data set where a patient is still alive at the last check-up, a customer has not cancelled yet, a machine is still running, a trial ends before half the cohort has an outcome. Those rows are right-censored: you do not know their event time, you only know it is greater than what you observed — and that is real information, not a missing value. The two obvious fixes are both catastrophically wrong, and this page shows you the damage numerically: deleting censored rows throws away exactly the subjects who lasted longest and pulls the estimate down, while counting a censoring as an event pretends everyone who walked out the door died on the way. The fix is the Kaplan-Meier product-limit estimator, S(t) = Π (1 − dᵢ/nᵢ): instead of one global average it chains together conditional survival probabilities computed only over the risk set — the people actually still being watched at that instant — so a censored subject contributes to every denominator up to the moment it leaves, then silently stops counting. Around that one idea everything else assembles: Greenwood's formula for the variance and the log-log confidence band that cannot escape [0,1], median survival read straight off the step curve (and why it can be genuinely undefined), the log-rank test comparing two curves by accumulating observed-minus-expected events over every risk set into a χ² with 1 degree of freedom, the Nelson-Aalen cumulative hazard Ĥ(t)=Σ dᵢ/nᵢ with S ≈ exp(−H), and finally Cox proportional hazards — the regression that never models the baseline hazard at all, maximising a partial likelihood built only from who-beat-whom inside each risk set, and returning a hazard ratio e^β. Everything below runs live in your browser with no libraries: generate a cohort, watch the two wrong answers diverge from Kaplan-Meier while KM tracks the true curve, step through the product-limit ledger row by risk-set row, split into two groups and watch the log-rank χ² and its hand-rolled p-value form, and score the real Cox partial likelihood across a grid of β to see where it peaks. (Nothing here is approximated or faked — exact product-limit, exact Greenwood, exact hypergeometric log-rank, an erfc-based χ²(1) tail written by hand, and a real Breslow partial likelihood. A Node suite checks the shipped code against independent brute-force baselines and passes 78/78 assertions.)

A row that has not finished yet still tells you something. A subject censored at month 9 did not survive 9 months — it survived at least 9 months, and that inequality is data. Kaplan-Meier is the estimator that spends it correctly: S(t) = Π (1 − dᵢ/nᵢ) over the ordered event times, each factor a conditional "given you made it this far, you survive this instant", each denominator the live risk set. Greenwood gives it error bars, the log-rank test compares two of these curves without assuming any distribution, Nelson-Aalen turns the same risk sets into a cumulative hazard, and Cox turns hazard into a regression. All of it is implemented from scratch below and runs live.

🔨 Build it yourself

    
Survival analysis is one bookkeeping pass and five short formulas on top of it. Below is the exact runnable core the LOOK tab uses — the risk table, the product-limit estimator, Greenwood, the median, the two wrong estimators, Nelson-Aalen, the log-rank test with a hand-rolled χ²(1) tail, and the Cox partial likelihood. Roughly 120 lines of arithmetic, no dependencies.

    
    

      
  1. 
        
    1
    The data shape — a time and a flag, never just a time
    
        
    Every row in survival data is a pair: how long you watched, and whether the thing you were waiting for actually happened. e = 1 means the event occurred at t. e = 0 means the subject was still event-free when you stopped watching at t — the true event time exists, you just know only that it is bigger than t. Losing that flag is the single most common way to destroy a survival dataset, because the two kinds of row look identical in a spreadsheet.
    
        
    // one row = { t: follow-up time, e: 1 event / 0 right-censored, g: group }
const cohort = [
  { t: 6,  e: 1, g: 0 },   // event at 6
  { t: 6,  e: 0, g: 0 },   // still event-free at 6 — true time is UNKNOWN, but > 6
  { t: 10, e: 1, g: 1 },
  { t: 13, e: 0, g: 1 },
];

// generating one: an exponential clock, and an independent dropout clock
function makeCohort(n, lambda, censorRate, rng) {
  const rows = [];
  for (let i = 0; i < n; i++) {
    const T = -Math.log(1 - rng()) / lambda;                 // the true event time
    const C = censorRate <= 0 ? Infinity
            : -Math.log(1 - rng()) / (lambda * censorRate / (1 - censorRate));
    const t = Math.min(T, C);
    rows.push({ t: Math.round(t * 10) / 10, e: T <= C ? 1 : 0 });
  }
  return rows;
}
// with rate lambda the TRUE survival curve is exactly S(t) = exp(-lambda*t),
// so every estimator on this page can be scored against a known answer.

  2. 
        
    2
    The risk table — one pass that conserves every subject
    
        
    Everything downstream reads from this one table. Walk the distinct times in order; at each time record n = how many subjects are still under observation, d = how many had the event right now, c = how many were censored right now. Then n drops by exactly d + c before the next time. The tie convention matters and is standard: someone censored at time t is counted as still at risk at t, because they were alive when the deaths happened. Two invariants fall out and make excellent tests: n at each time equals #{tⱼ ≥ t}, and Σd + Σc = n₀.
    
        
    function riskTable(rows) {
  const times = [...new Set(rows.map(r => r.t))].sort((a, b) => a - b);
  const out = [];
  let n = rows.length;                       // everybody starts at risk
  for (const t of times) {
    let d = 0, c = 0;
    for (const r of rows) if (r.t === t) { if (r.e === 1) d++; else c++; }
    out.push({ t, n, d, c });                // n = #{ t_j >= t }, by construction
    n -= d + c;                              // they leave AFTER this instant
  }
  return out;
}
// invariant 1:  every row's n equals rows.filter(r => r.t >= t).length
// invariant 2:  sum(d) + sum(c) === rows.length     — nobody is lost or duplicated

  3. 
        
    3
    Kaplan-Meier — a product of conditional survivals
    
        
    The estimator is one line inside the loop: at each time where somebody actually died, multiply the running survival by 1 − dᵢ/nᵢ, the probability of getting through that instant given you reached it. Times where only censoring happened contribute no factor — but they have already done their job, because those subjects sat in earlier denominators. That is the whole trick: censored rows are counted for as long as they were observed and then stop counting, instead of being deleted or fabricated into events.
    
        
    function kaplanMeier(rows, z = 1.96) {
  const table = riskTable(rows);
  const steps = [];
  let S = 1, gw = 0, H = 0;                      // gw = Greenwood sum, H = Nelson-Aalen
  for (const r of table) {
    if (r.d === 0) continue;                     // censoring alone does NOT step the curve
    S *= 1 - r.d / r.n;                          // <-- the product-limit estimator
    H += r.d / r.n;                              // <-- cumulative hazard, same risk sets
    if (r.n > r.d) gw += r.d / (r.n * (r.n - r.d));
    steps.push({ t: r.t, n: r.n, d: r.d, c: r.c, S, H,
                 se: S * Math.sqrt(gw), ...logLogCI(S, gw, z) });
  }
  return { n0: rows.length, table, steps };
}

function sAt(km, t) {                            // right-continuous step lookup
  let S = 1;
  for (const s of km.steps) { if (s.t <= t + 1e-12) S = s.S; else break; }
  return S;
}
// with NO censoring this is exactly the empirical survival #{t_i > t} / n —
// the product telescopes, because then n_{i+1} = n_i - d_i.

    Greenwood's variance and a band that stays inside [0,1]
    
        
    Ŝ is a product of independent-ish binomial proportions, so push the variance through with the delta method: Var(Ŝ) = Ŝ² · Σ dᵢ/(nᵢ(nᵢ−dᵢ)). That is Greenwood's formula, and it is not a heuristic — it is exactly what the derivative calculation gives, which is why the test can recompute it by finite differences and get the same number. The naive band Ŝ ± 1.96·se then embarrasses you by poking above 1 near the start and below 0 in the tail, so build the interval on log(−log Ŝ) instead, where the parameter is unbounded, and map it back by exponentiation. The band is asymmetric on purpose.
    
        
    function logLogCI(S, gw, z) {
  if (S >= 1) return { lo: 1, hi: 1 };
  if (S <= 0) return { lo: 0, hi: 0 };
  const se = Math.sqrt(gw) / Math.abs(Math.log(S));   // se of log(-log S)
  const f  = Math.exp(z * se);
  return { lo: Math.pow(S, f), hi: Math.pow(S, 1 / f) };  // always inside [0,1]
}
// Var(S) = S^2 * sum( d / (n*(n-d)) )       <- Greenwood
// se(S)  = S * sqrt(gw)
// the naive S +/- z*se band leaks outside [0,1]; the log-log one cannot.

    Median survival — and why it is often just missing
    
        
    Do not average the follow-up times; that number is meaningless when half your rows are censored. The median survival is read off the curve: the first time at which Ŝ(t) ≤ 0.5. If heavy censoring or a short study means the curve never gets down to 0.5, the median genuinely does not exist in your data and the honest report is "not reached" — not the mean, not the last observed time, and definitely not a number you extrapolated. The same lookup gives any other quantile.
    
        
    function medianSurvival(km) {
  for (const s of km.steps) if (s.S <= 0.5 + 1e-12) return s.t;
  return null;                     // "not reached" — a legitimate answer, report it
}

function quantileSurvival(km, q) {          // q = 0.25 -> the 25th percentile of TIME
  for (const s of km.steps) if (s.S <= 1 - q + 1e-12) return s.t;
  return null;
}
// mean(rows.map(r => r.t)) is NOT the mean survival time whenever anything is censored.
// restricted mean survival time (RMST) = area under the KM curve up to a horizon,
//   RMST(tau) = integral_0^tau S(t) dt  — a well-defined alternative when the median is not reached.

    The two wrong ways, coded so you can watch them fail
    
        
    It is worth implementing the mistakes, because both are one line and both look reasonable until you plot them. Dropping the censored rows keeps only subjects who had the event, which is precisely a sample of the shorter lifetimes — the estimate collapses. Recoding a censoring as an event is even more aggressive: it asserts that everyone who left the study died on their way out. Both bias survival downwards, and the demo shows the gap widening as the censoring rate rises, with Kaplan-Meier tracking the true curve throughout.
    
        
    // WRONG #1 — complete-case analysis: delete anyone who did not have the event
const dropCensored = rows => kaplanMeier(rows.filter(r => r.e === 1));

// WRONG #2 — pretend the censoring WAS the event
const censoredAsEvent = rows => kaplanMeier(rows.map(r => ({ ...r, e: 1 })));

// RIGHT — every row contributes to the denominators it earned, then leaves
const right = kaplanMeier(rows);

// with lambda = 0.10 and 45% censoring on 80 subjects the true median is 6.93:
//   drop censored     -> ~4.1   (far too pessimistic)
//   censored = event  -> ~4.5   (far too pessimistic)
//   Kaplan-Meier      -> ~6.7   (right, and it stays right as censoring grows)

    Hazard — Nelson-Aalen, and why exp(−H) ≈ S
    
        
    Survival answers "what fraction is left?". Hazard answers a sharper question: "given you are still here, how intense is the risk right now?". Its cumulative version is even simpler than Kaplan-Meier — just add dᵢ/nᵢ instead of multiplying 1 − dᵢ/nᵢ. Since log(1−x) ≈ −x for small x, exp(−Ĥ) and Ŝ agree closely whenever the per-step hazards are small, and Nelson-Aalen behaves better in small samples. It is also the natural quantity to model, because hazards multiply cleanly — which is exactly what Cox exploits next.
    
        
    function nelsonAalen(rows) {
  const out = []; let H = 0, V = 0;
  for (const r of riskTable(rows)) {
    if (r.d === 0) continue;
    H += r.d / r.n;                       // ADD the hazard instead of multiplying survival
    V += r.d / (r.n * r.n);               // Aalen's variance estimate
    out.push({ t: r.t, H, se: Math.sqrt(V), Sna: Math.exp(-H) });
  }
  return out;
}
// h(t) = -d/dt log S(t)          H(t) = integral_0^t h(u) du         S(t) = exp(-H(t))
// KM factor  1 - d/n     vs      NA increment  d/n
// log(1-x) = -x - x^2/2 - ...    so exp(-H) >= S always, with the gap ~ sum (d/n)^2 / 2

    The log-rank test — observed minus expected, one risk set at a time
    
        
    To compare two curves without assuming any distribution, freeze time at each pooled event time and ask a tiny question: of the dᵢ deaths happening now, how many would land in group B if the groups were interchangeable? That is a hypergeometric draw, so the expectation is dᵢ·n_Bᵢ/nᵢ and the variance has a closed form. Accumulate observed minus expected across every risk set, standardise, and you have a χ² with 1 degree of freedom. The identity worth remembering — and worth asserting in a test — is that summed over both groups the observed and expected totals are equal by construction.
    
        
    function logRank(rows) {                     // rows carry g = 0 or 1
  const times = [...new Set(rows.filter(r => r.e === 1).map(r => r.t))].sort((a,b) => a-b);
  let O1 = 0, E1 = 0, V = 0, O0 = 0, E0 = 0;
  const tab = [];
  for (const t of times) {
    let n = 0, n1 = 0, d = 0, d1 = 0;
    for (const r of rows) {
      if (r.t >= t)               { n++;  if (r.g === 1) n1++; }   // the risk set NOW
      if (r.t === t && r.e === 1)  { d++;  if (r.g === 1) d1++; }
    }
    const e1 = d * n1 / n;                                          // hypergeometric mean
    const v  = n > 1 ? d * (n1/n) * (1 - n1/n) * (n - d) / (n - 1) : 0;
    O1 += d1; E1 += e1; O0 += d - d1; E0 += d - e1; V += v;
    tab.push({ t, n, n1, d, d1, e1, v });
  }
  const chi2 = V > 0 ? (O1 - E1) * (O1 - E1) / V : 0;
  return { tab, O1, E1, O0, E0, V, chi2, p: chi2sf1(chi2),
           hrOE: (O1 / E1) / (O0 / E0) };          // the O/E hazard-ratio estimate
}
// ALWAYS TRUE: O1 + O0 === E1 + E0 === total events.  A broken loop breaks this first.

    The p-value, without a stats library
    
        
    A χ² with one degree of freedom is the square of a standard normal, so its upper tail collapses to a single special function: P(X > x) = erfc(√(x/2)). Write erfc yourself with a Taylor series for small arguments and a continued fraction for large ones and you get full double precision with about fifteen lines and zero dependencies. The test checks it against the χ²(1) density integrated numerically by Simpson's rule — after the substitution u = √x which removes the singularity at zero — and the two agree to better than 1e-9.
    
        
    function erfSeries(x) {                       // |x| <~ 3
  let term = x, sum = x; const x2 = x * x;
  for (let k = 1; k < 300; k++) {
    term *= -x2 / k;
    const add = term / (2 * k + 1); sum += add;
    if (Math.abs(add) < 1e-18 * Math.abs(sum)) break;
  }
  return 2 / Math.sqrt(Math.PI) * sum;
}
function erfcCF(x) {                          // large x, modified Lentz continued fraction
  const tiny = 1e-300; let f = tiny, C = f, D = 0;
  for (let k = 1; k <= 400; k++) {
    const a = (k === 1) ? 1 : (k - 1) / 2, b = x;
    D = b + a * D; if (Math.abs(D) < tiny) D = tiny;
    C = b + a / C; if (Math.abs(C) < tiny) C = tiny;
    D = 1 / D; const delta = C * D; f *= delta;
    if (Math.abs(delta - 1) < 1e-16) break;
  }
  return Math.exp(-x * x) / Math.sqrt(Math.PI) * f;
}
const erfc    = x => x < 0 ? 2 - erfc(-x) : (x < 3 ? 1 - erfSeries(x) : erfcCF(x));
const chi2sf1 = x => x <= 0 ? 1 : erfc(Math.sqrt(x / 2));    // P(chi2_1 > x)
const normCdf = x => 0.5 * erfc(-x / Math.SQRT2);

// chi2sf1(3.841459) = 0.05000   chi2sf1(6.634897) = 0.01000   chi2sf1(10.827566) = 0.001

    Cox proportional hazards — the likelihood that skips the baseline
    
        
    Cox's model says h(t | x) = h₀(t)·e^{βx}: an unspecified baseline hazard shared by everyone, multiplied by a covariate effect. The trick is that you never have to estimate h₀. Condition on the fact that somebody died at each event time and ask only "which member of the risk set was it?" — the baseline cancels top and bottom, leaving a partial likelihood in β alone. That is what "semi-parametric" means here: fully parametric in the covariates, completely free in time. At β = 0 the log-likelihood is just −Σ log nᵢ, which is a good hand-checkable anchor, and scanning a grid of β shows a single clean peak whose exponential is the hazard ratio.
    
        
    // Breslow partial log-likelihood for one covariate x
function coxLogLik(rows, beta) {
  let ll = 0;
  for (const r of rows) {
    if (r.e !== 1) continue;                        // only events contribute a term
    let s = 0;
    for (const j of rows) if (j.t >= r.t) s += Math.exp(beta * j.x);   // the risk set
    ll += beta * r.x - Math.log(s);                 // h0(t) cancelled — it is not here
  }
  return ll;
}
function coxScore(rows, beta) {                     // the analytic derivative
  let u = 0;
  for (const r of rows) {
    if (r.e !== 1) continue;
    let s = 0, sx = 0;
    for (const j of rows) if (j.t >= r.t) { const w = Math.exp(beta * j.x); s += w; sx += w * j.x; }
    u += r.x - sx / s;
  }
  return u;
}
function coxGrid(rows, lo = -3, hi = 3, m = 241) {  // score it, do not trust it blindly
  let best = -Infinity, bHat = 0; const pts = [];
  for (let i = 0; i < m; i++) {
    const b = lo + (hi - lo) * i / (m - 1), ll = coxLogLik(rows, b);
    pts.push([b, ll]);
    if (ll > best) { best = ll; bHat = b; }
  }
  return { pts, bHat, best, hr: Math.exp(bHat) };   // e^beta IS the hazard ratio
}
// coxLogLik(rows, 0) === -sum(log(n_i)) over event times — hand-checkable.
// coxScore(rows, bHat) is ~0 at the maximiser, which is how the test verifies the grid.

    In practice — the standard tools and the traps
    
        
    In Python you would reach for lifelines or scikit-survival; in R, survival. Four traps catch everyone: censoring must be non-informative (people who drop out cannot be dropping out because they are about to have the event), the proportional-hazards assumption must be checked rather than assumed, a p-value from the log-rank says nothing about effect size, and a median that was never reached must be reported as "not reached" instead of quietly filled in.
    
        
    from lifelines import KaplanMeierFitter, CoxPHFitter
from lifelines.statistics import logrank_test

km = KaplanMeierFitter().fit(df.time, df.event, label="arm A")
km.plot(ci_show=True)                  # the same product-limit + Greenwood band
km.median_survival_time_               # inf when the curve never reaches 0.5

res = logrank_test(a.time, b.time, a.event, b.event)
res.test_statistic, res.p_value        # chi2 on 1 df, and its tail

cph = CoxPHFitter().fit(df, "time", "event")
cph.summary                            # coef = beta, exp(coef) = hazard ratio
cph.check_assumptions(df)              # PH is an ASSUMPTION — test it (Schoenfeld residuals)

# traps:
#  * informative censoring breaks everything upstream of the estimator
#  * crossing curves => hazards are NOT proportional; log-rank loses power, Cox misleads
#    -> use RMST differences, or a time-varying coefficient / stratified Cox
#  * "p < 0.05" is not an effect size — report the HR and its confidence interval
#  * competing risks (dying of something else) need Aalen-Johansen, not 1 - KM

The most common mistake in industry churn modelling is quietly using D2's logistic regression on "did they cancel in the last 90 days?" — which throws away the timing, forces an arbitrary horizon, and mislabels every customer who has not been around for 90 days yet. Kaplan-Meier and Cox exist precisely so that you do not have to make that choice.

    


    
🎉 Day 60 of MachineLearningFromZero done — the estimator that gets an answer out of the rows that have not finished yet.
Right-censoring is not missing data: a subject last seen event-free at month 9 tells you their true time exceeds 9, and both obvious workarounds — deleting them or calling it an event — bias survival downwards, badly, in a way that grows with the censoring rate. The Kaplan-Meier product-limit estimator Ŝ(t)=Π(1−dᵢ/nᵢ) fixes it in the denominators: a censored subject counts in every risk set up to the moment it leaves and then stops, so no information is invented and none is thrown away. Greenwood gives the curve error bars and the log-log transform keeps the band inside [0,1]; the median is a lookup, and "not reached" is a legitimate answer; the log-rank test compares two curves by accumulating observed-minus-expected over every risk set into a χ²(1); Nelson-Aalen converts the same sums into a cumulative hazard with Ŝ ≈ exp(−Ĥ); and Cox proportional hazards turns that into a regression by maximising a partial likelihood in which the baseline hazard cancels entirely, returning a hazard ratio e^β̂. The costs are honest ones: censoring must be non-informative, proportional hazards is an assumption you have to test, and a p-value is not an effect size. 👉 Whenever your outcome is "how long until…" and some rows have not got there yet, this is the toolkit — everything else quietly throws those rows away.
