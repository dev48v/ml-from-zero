MachineLearningFromZero · Day 52

🪨 Huber Regression — a fit that bends but doesn't break when a few points go bad. Ordinary least squares minimises the sum of squared residuals, so a point twice as far off pays four times the penalty and a point ten times as far pays a hundred — the fit is dragged toward whichever point is worst, and its breakdown point is zero. Huber keeps least-squares' smooth, convex world but caps that runaway growth: it uses the quadratic ½r² only while a residual stays inside a knee |r| ≤ δ, and switches to a linear penalty δ(|r| − ½δ) beyond it. Squaring near zero keeps OLS's efficiency on clean Gaussian noise; the linear tails mean a far-off point's influence stops growing — it pulls with a bounded, constant force instead of one that explodes with distance. You fit it not by a magic formula but by iteratively reweighted least squares: refit an ordinary weighted line, where each point's weight is w = min(1, δ/|r|) — full weight inside the knee, gently discounted outside — and repeat until it settles. Unlike RANSAC (Day 51), which throws points away and samples for a consensus, Huber uses every point with one smooth loss — so it sits between ordinary least-squares and a fully-robust fit. Everything below runs live in your browser — scatter outliers (click to add your own), watch IRLS reweight and converge with a δ slider, see least-squares dragged away for contrast, and read the Huber loss against the squared loss so you can see the linear tails.

Least squares has no defence against a far-off point. Because it minimises the sum of squared residuals, a single outlier — whose squared error is enormous — can pivot the whole fitted line toward itself. Huber regression softens exactly that. It keeps the smooth quadratic penalty ½r² for residuals inside a knee |r| ≤ δ, so on honest, near-Gaussian noise it behaves just like OLS; but once a residual exceeds δ the penalty grows only linearly, δ(|r| − ½δ), so a wild point contributes a bounded, constant pull instead of one that explodes with distance. The fit is found by iteratively reweighted least squares: refit a weighted line where each point's weight is min(1, δ/|r|) — full inside the knee, gently discounted in the tails — and repeat until it settles. Every point still counts; none is thrown away. 🔨 Build it yourself

    
Huber regression is barely more code than ordinary least squares — the exact routine the LOOK tab runs, no scikit-learn black box. Below is the runnable core: the Huber loss with its quadratic core and linear tails, the weight function that turns it into a reweighting rule, one pass of weighted least squares, the IRLS loop that repeats until it settles, and how to set δ from the noise scale. Every line the LOOK tab draws comes from these snippets.

    
    
      
  1. 
        
    1
    The Huber loss — quadratic core, linear tails
    
        
    This is the whole idea in one function. While a residual stays inside the knee |r| ≤ δ it is penalised by the ordinary squared loss ½r² — so on clean, near-Gaussian data Huber behaves exactly like least squares. Past the knee it switches to a linear penalty δ(|r| − ½δ), chosen so the two pieces meet smoothly in both value and slope. A point ten times δ away costs about 10δ², not 50δ² — the runaway squared growth is gone.
    
        
    function huberLoss(r, d) {           // d = delta, the knee
  const a = Math.abs(r);
  return a <= d ? 0.5 * r * r        // quadratic core (like OLS)
                : d * (a - 0.5 * d); // linear tail (bounded growth)
}
// the two pieces join smoothly: same value AND same slope at |r| = d
    
      
    2. 
      
  2. 
        
    2
    The weight — how the linear tail becomes a reweighting
    
        
    The trick that makes Huber fittable with plain least-squares machinery: its derivative (the influence) is ψ(r) = r inside the knee and a constant ±δ outside — capped. Divide the influence by r and you get a weight w(r) = min(1, δ/|r|): full weight for points in the quadratic core, and a discount δ/|r| that shrinks the further out a point is. That single line is why outliers pull less — they are literally scaled down before the fit sees them.
    
        
    const huberWeight = (r, d) => {
  const a = Math.abs(r);
  return a <= d ? 1 : d / a;   // 1 in the core, δ/|r| in the tails
};
// ψ(r) = r · w(r): capped at ±δ, so a point's PULL never grows past δ
    
      
    3. 
      
  3. 
        
    3
    One weighted least-squares pass
    
        
    Given the weights, fitting a line is the closed-form weighted least squares — the same normal equations as OLS with each sum weighted by wᵢ. Down-weighted outliers contribute a fraction of a point to every sum, so the line barely notices them. This is the estimation half; the weights above are the robustness half.
    
        
    function wlsFit(pts, w) {              // weighted least-squares line
  let Sw=0, Swx=0, Swy=0, Swxx=0, Swxy=0;
  for (let i = 0; i < pts.length; i++) {
    const p = pts[i], wi = w[i];
    Sw += wi; Swx += wi*p.x; Swy += wi*p.y;
    Swxx += wi*p.x*p.x; Swxy += wi*p.x*p.y;
  }
  const den = Sw*Swxx - Swx*Swx;
  const m = (Sw*Swxy - Swx*Swy) / den;
  return { m, b: (Swy - m*Swx) / Sw };
}
    
      
    4. 
      
  4. 
        
    4
    The IRLS loop — reweight, refit, repeat
    
        
    That is the entire algorithm. Start from an ordinary least-squares line, compute each point's residual, turn residuals into Huber weights, refit the weighted line, and repeat. Because the Huber loss is convex, this iteration converges to the one global minimum — usually in a handful of passes — no local optima, no randomness, no threshold to tune a consensus. Watch it settle in the LOOK tab.
    
        
    function huberFit(pts, d, iters = 50) {
  let model = olsFit(pts);                     // start from OLS
  for (let k = 0; k < iters; k++) {
    const w = pts.map(p =>                     // reweight by residual
      huberWeight(p.y - (model.m*p.x + model.b), d));
    const next = wlsFit(pts, w);               // refit weighted line
    if (Math.abs(next.m - model.m) < 1e-9) { model = next; break; }
    model = next;                              // repeat until settled
  }
  return model;             // the robust line — every point used
}
    
      
    5. 
      
  5. 
        
    5
    Choosing δ — scale it to the noise
    
        
    δ is the knee between "honest noise" and "outlier". Because it lives in residual units, a fit that scales with the data must set it relative to the noise spread σ. The standard choice is δ = 1.345·σ, which gives 95% of OLS's efficiency on clean Gaussian data while still clipping gross errors — so proper implementations standardise residuals by a robust σ (via the MAD) and use the scale-free constant 1.345. The LOOK tab keeps δ in raw units so the knee lines up visibly with the loss plot.
    
        
    # robust scale, then the 95%-efficient tuning constant
import numpy as np
resid = np.abs(y - (m*x + b))
sigma = 1.4826 * np.median(np.abs(resid - np.median(resid)))  # MAD → σ
delta = 1.345 * sigma       # standard Huber knee: 95% efficient, robust
# small δ → closer to L1 / median (more robust, less efficient)
# large δ → closer to OLS (δ → ∞ IS ordinary least squares)

  6.

    In practice — the standard tools
    
        
    You will rarely hand-roll it. scikit-learn's HuberRegressor fits the Huber loss (its epsilon is δ in standardised units, default 1.35) and jointly estimates the scale, handing back coefficients plus an outliers_ mask. statsmodels' RLM exposes the whole family of M-estimators — Huber, Tukey's bisquare, and more — over the same IRLS engine.
    
        
    # scikit-learn — robust linear regression
from sklearn.linear_model import HuberRegressor
h = HuberRegressor(epsilon=1.35).fit(X, y)   # epsilon = δ (standardised)
robust_line = (h.coef_, h.intercept_)
outliers    = h.outliers_        # points that fell in the linear tails

# statsmodels — the M-estimator family over the same IRLS
import statsmodels.api as sm
rlm = sm.RLM(y, sm.add_constant(x), M=sm.robust.norms.HuberT()).fit()

The trade is how much contamination you expect and how smooth you need the fit to be. OLS is optimal on Gaussian noise and useless the instant one high-leverage point appears. Huber is the gentle middle: it keeps least-squares' smooth, convex, efficient behaviour on the bulk of the data and only grades the tails down to linear, so it shrugs off a few mild outliers while still — being an all-points estimator — bending toward a truly gross high-leverage point (its breakdown point stays near zero). LAD (L1) is Huber's δ→0 limit, the median line: more robust, but kinked and less efficient. Theil–Sen takes the median of all pairwise slopes — elegant, deterministic, robust to ~29% contamination, but O(n²). RANSAC (Day 51) makes the opposite bet: it throws points away and samples for a consensus, tolerating well past half the data as garbage — but it is random, needs a threshold, and is not smooth. Huber's genius is that it changes nothing about the least-squares workflow except one weighting line, buying real robustness against mild outliers while staying convex, deterministic, and statistically efficient. The moment your outliers become many or high-leverage, hand off to a sampling method like RANSAC.

Huber regression keeps least-squares' smooth, convex world but caps its fatal sensitivity to far-off points. It penalises a residual with the ordinary quadratic ½r² while it stays inside a knee |r| ≤ δ — so on clean, near-Gaussian noise it is just OLS, keeping 95% efficiency at the standard δ = 1.345σ — and switches to a linear penalty δ(|r| − ½δ) beyond it, so an outlier's influence stops growing and is capped at ±δ instead of exploding with distance. You fit it by iteratively reweighted least squares: refit a weighted line with weights min(1, δ/|r|) — full inside the knee, discounted in the tails — until it settles, which it always does, because the loss is convex with one global minimum. Every point is used; none is discarded. That places Huber between ordinary least-squares and a fully-robust fit: large δ recovers OLS, small δ approaches the median line, and δ ≈ 1.345σ balances the two. Its limit is honest — because it still touches every point, a truly gross or high-leverage outlier can bend it, so its breakdown point stays near zero. 👉 When your data is mostly clean with a handful of mild outliers and you want to keep least-squares' smoothness and efficiency, reach for Huber; when outliers become many or high-leverage, switch to a sampling method like RANSAC (Day 51).
