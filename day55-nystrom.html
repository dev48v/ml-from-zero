MachineLearningFromZero · Day 55

🧩 The Nyström method — the trick that lets kernel machines survive at scale. Every kernel method — SVM, Gaussian processes, kernel PCA, spectral clustering — never looks at your raw features; it looks only at the n×n matrix K of pairwise similarities Kᵢⱼ = k(xᵢ,xⱼ). That matrix is a monster: n = 100,000 points is 10 billion entries — tens of gigabytes you can't store and an O(n³) solve you can't afford. Nyström buys its way out by sampling: pick m ≪ n landmark points, compute only the thin n×m block C of kernel values from every point to the landmarks and the tiny m×m block W among the landmarks themselves, and reconstruct the entire matrix as K ≈ C W⁺ Cᵀ. The whole giant is rebuilt from a strip of columns and one small pseudo-inverse. It is exact when the landmarks are all the points (m = n ⇒ C = W = K and K W⁺ Kᵀ = K), and the reconstruction error ‖K − K̃‖_F / ‖K‖_F falls fast as m grows because a smooth RBF kernel's eigenvalues decay quickly — the matrix is nearly low-rank, so a handful of well-spread landmarks already capture it. Everything below runs live in your browser: real 2-D points, an RBF kernel built by hand, landmarks chosen at random or spread out farthest-point style, a from-scratch Jacobi eigen-solve for the tiny W⁺, the reconstruction C W⁺ Cᵀ, side-by-side kernel heatmaps with an error map, and an error-vs-m curve diving toward zero — the same "approximate the expensive object" bet as random projections (Day 54), but pointed at the kernel matrix instead of the distances.

You can rebuild a giant kernel matrix from a few landmark points. Sample m ≪ n landmarks, measure the kernel only from every point to those landmarks (C, size n×m) and among the landmarks (W, size m×m), and the whole n×n matrix comes back as K ≈ C W⁺ Cᵀ. That is the Nyström method, and it works because a smooth kernel matrix is nearly low-rank — its eigenvalues decay, so a few landmarks span almost everything. Below it is built from scratch, live — the RBF kernel, the landmark sampler, the tiny hand-rolled pseudo-inverse of W, the reconstruction, the error heatmap, and the error-vs-m curve — on data you choose and reshape yourself.

🔨 Build it yourself

    
The Nyström method is short — the exact routine the LOOK tab runs, no scikit-learn black box. Below is the runnable core: the RBF kernel and the two cheap blocks C and W, a from-scratch Jacobi eigen-decomposition of the tiny symmetric W, the pseudo-inverse W⁺ built from those eigenpairs (with a whisker of diagonal jitter for stability), the reconstruction C W⁺ Cᵀ, the two landmark samplers, and the Frobenius error. Every heatmap and curve the LOOK tab draws comes from these snippets.

    
    
      
  1. 
        
    1
    The RBF kernel and the two cheap blocks C and W
    
        
    The kernel is one line: k(x,y) = exp(−γ‖x−y‖²). The whole point of Nyström is to never form the full n×n matrix. Instead we compute only C — kernel values from every point to the m landmarks (n×m) — and W, the landmark-to-landmark block (m×m). Both are cheap: O(nm) and O(m²). Note W is exactly the landmark rows of C, so it is symmetric positive semi-definite.
    
        
    // RBF kernel between two 2-D points
function rbf(ax, ay, bx, by, gamma) {
  const dx = ax - bx, dy = ay - by;
  return Math.exp(-gamma * (dx*dx + dy*dy));
}
// C: n×m kernel to landmarks   ·   W: m×m among landmarks
function buildCW(xs, ys, land, n, m, gamma) {
  const C = new Float64Array(n * m), W = new Float64Array(m * m);
  for (let i = 0; i < n; i++)
    for (let a = 0; a < m; a++) {
      const l = land[a];
      C[i*m + a] = rbf(xs[i], ys[i], xs[l], ys[l], gamma);
    }
  for (let a = 0; a < m; a++)
    for (let b = 0; b < m; b++) {
      const la = land[a], lb = land[b];
      W[a*m + b] = rbf(xs[la], ys[la], xs[lb], ys[lb], gamma);
    }
  return { C, W };                       // never build the full n×n K
}
    
      
    2. 
      
  2. 
        
    2
    Diagonalise the tiny W — a hand-rolled Jacobi eigensolver
    
        
    Because W is small (m ≤ 12) and symmetric, the classic Jacobi rotation algorithm diagonalises it with nothing but sines and cosines — repeatedly rotating away the largest off-diagonal entry until W = V Λ Vᵀ. No library, no SVD. The columns of V are the eigenvectors, Λ the eigenvalues — everything we need to build a pseudo-inverse.
    
        
    // Jacobi eigen-decomposition of a symmetric m×m matrix
function jacobiEigen(Ain, m) {
  const A = Float64Array.from(Ain);
  const V = new Float64Array(m*m);
  for (let i = 0; i < m; i++) V[i*m + i] = 1;         // V starts as I
  for (let sweep = 0; sweep < 100; sweep++) {
    let off = 0;
    for (let p = 0; p < m; p++) for (let q = p+1; q < m; q++) off += A[p*m+q]**2;
    if (off < 1e-24) break;                            // converged
    for (let p = 0; p < m; p++) for (let q = p+1; q < m; q++) {
      const apq = A[p*m+q]; if (Math.abs(apq) < 1e-300) continue;
      const theta = (A[q*m+q] - A[p*m+p]) / (2*apq);   // stable rotation
      const t = Math.sign(theta || 1) / (Math.abs(theta) + Math.sqrt(theta*theta + 1));
      const c = 1 / Math.sqrt(t*t + 1), s = t*c;
      for (let k = 0; k < m; k++) {                    // rotate columns p,q
        const akp = A[k*m+p], akq = A[k*m+q];
        A[k*m+p] = c*akp - s*akq;  A[k*m+q] = s*akp + c*akq;
      }
      for (let k = 0; k < m; k++) {                    // rotate rows p,q
        const apk = A[p*m+k], aqk = A[q*m+k];
        A[p*m+k] = c*apk - s*aqk;  A[q*m+k] = s*apk + c*aqk;
      }
      for (let k = 0; k < m; k++) {                    // accumulate V
        const vkp = V[k*m+p], vkq = V[k*m+q];
        V[k*m+p] = c*vkp - s*vkq;  V[k*m+q] = s*vkp + c*vkq;
      }
    }
  }
  const vals = new Float64Array(m);
  for (let i = 0; i < m; i++) vals[i] = A[i*m + i];    // eigenvalues on diagonal
  return { vals, vecs: V };
}
    
      
    3. 
      
  3. 
        
    3
    The pseudo-inverse W⁺ — invert the eigenvalues, drop the tiny ones
    
        
    A kernel block W can be rank-deficient (two landmarks nearly identical ⇒ a near-zero eigenvalue), so a plain inverse blows up. The Moore–Penrose pseudo-inverse is the fix: W⁺ = V Λ⁺ Vᵀ, where Λ⁺ inverts each eigenvalue above a tolerance and zeros the rest. A tiny jitter on the diagonal keeps everything positive and stable — exactly the trick the LOOK tab uses so the reconstruction never NaNs.
    
        
    // Moore–Penrose pseudo-inverse of a symmetric PSD matrix W (m×m)
function pinvSym(W, m, jitter) {
  const A = Float64Array.from(W);
  for (let i = 0; i < m; i++) A[i*m + i] += jitter;    // ridge for stability
  const { vals, vecs } = jacobiEigen(A, m);
  let maxv = 0; for (let i = 0; i < m; i++) if (vals[i] > maxv) maxv = vals[i];
  const tol = maxv * 1e-9 + 1e-15;                      // rank cutoff
  const inv = new Float64Array(m*m);
  for (let a = 0; a < m; a++) for (let b = 0; b < m; b++) {
    let s = 0;
    for (let k = 0; k < m; k++) {
      const lam = vals[k];
      if (lam > tol) s += vecs[a*m+k] * vecs[b*m+k] / lam;   // 1/λ on kept modes
    }
    inv[a*m + b] = s;                                   // (V Λ⁺ Vᵀ)_ab
  }
  return inv;
}
    
      
    4. 
      
  4. 
        
    4
    The reconstruction — K̃ = C W⁺ Cᵀ
    
        
    The whole kernel comes back as C W⁺ Cᵀ. In practice you never materialise the n×n result — you keep the factor M = C W⁺ (size n×m) and multiply on demand, so a kernel-SVM or GP solve costs O(nm²) instead of O(n³). Here we do form entries just to measure the error. When the landmarks are all the points (m = n), C = W = K and K W⁺ Kᵀ = K exactly — the pseudo-inverse's defining property — so the approximation is perfect.
    
        
    // M = C · W⁺   (n×m) — the compact factor you actually keep
function reconstructFactor(C, Winv, n, m) {
  const M = new Float64Array(n * m);
  for (let i = 0; i < n; i++)
    for (let a = 0; a < m; a++) {
      let s = 0;
      for (let b = 0; b < m; b++) s += C[i*m + b] * Winv[b*m + a];
      M[i*m + a] = s;
    }
  return M;                              // K̃ = M · Cᵀ , never stored in full
}
// a single reconstructed kernel entry K̃[i][j]
function ktilde(M, C, i, j, m) {
  let s = 0;
  for (let a = 0; a < m; a++) s += M[i*m + a] * C[j*m + a];
  return s;                              // = row_i(C) · W⁺ · row_j(C)ᵀ
}
    
      
    5. 
      
  5. 
        
    5
    Choosing landmarks — random vs farthest-point spread
    
        
    Which points become landmarks matters enormously. Uniform random is the classic baseline but clumps in dense regions. Farthest-point sampling (a k-means++/k-centers cousin) greedily grows the set by always adding the point most distant from those already chosen — it blankets the cloud, so the same m landmarks buy far lower error. Principled schemes (leverage-score sampling) go further, weighting by how "hard to reconstruct" each column is.
    
        
    // uniform random landmarks — shuffle, take m
function selectRandom(n, m, rng) {
  const idx = [...Array(n).keys()];
  for (let i = n-1; i > 0; i--) {
    const j = Math.floor(rng() * (i+1));
    [idx[i], idx[j]] = [idx[j], idx[i]];
  }
  return idx.slice(0, m);
}
// farthest-point / k-centers spread — cover the cloud
function selectSpread(xs, ys, n, m, rng) {
  const chosen = [Math.floor(rng() * n)];
  const d2 = new Float64Array(n).fill(Infinity);
  while (chosen.length < m) {
    const last = chosen[chosen.length - 1];
    let best = -1, bestD = -1;
    for (let i = 0; i < n; i++) {
      const dx = xs[i]-xs[last], dy = ys[i]-ys[last];
      const dd = dx*dx + dy*dy;
      if (dd < d2[i]) d2[i] = dd;             // distance to nearest chosen
      if (d2[i] > bestD) { bestD = d2[i]; best = i; }
    }
    chosen.push(best);                         // add the most-distant point
  }
  return chosen;
}

    Measuring the error, and putting it together
    
        
    Quality is the relative Frobenius error ‖K − K̃‖_F / ‖K‖_F — square every entry's mismatch, sum, root, normalise. This is the number the error-vs-m curve plots. The full pipeline is six calls: build C, W, pinv W, form the factor, then sum the residual against the true kernel.
    
        
    function nystromError(xs, ys, n, land, m, gamma) {
  const { C, W } = buildCW(xs, ys, land, n, m, gamma);
  const Winv = pinvSym(W, m, 1e-9);           // tiny jitter → never NaN
  const M    = reconstructFactor(C, Winv, n, m);
  let num = 0, den = 0;
  for (let i = 0; i < n; i++)
    for (let j = 0; j < n; j++) {
      const ktrue = rbf(xs[i], ys[i], xs[j], ys[j], gamma);
      const e = ktrue - ktilde(M, C, i, j, m);
      num += e*e; den += ktrue*ktrue;
    }
  return Math.sqrt(num / den);                // relative Frobenius error → 0 as m→n
}

    In practice — the standard tools
    
        
    You rarely hand-roll it. scikit-learn ships Nystroem, which returns the explicit feature map Φ = C W^(−1/2) so that Φ Φᵀ ≈ K — feed Φ straight into any linear model to get a kernel model at linear cost. Gaussian-process libraries use the same idea under the name inducing points (sparse GPs), and it is the workhorse behind large-scale spectral clustering and kernel PCA.
    
        
    # scikit-learn — Nyström feature map in three lines
from sklearn.kernel_approximation import Nystroem
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline

model = make_pipeline(
    Nystroem(kernel='rbf', gamma=0.2, n_components=100),  # m = 100 landmarks
    Ridge())                                              # a LINEAR model on Φ
model.fit(X, y)        # kernel-quality fit at linear O(n·m²) cost, not O(n³)

All four are the same bet from Day 54 taken further: approximate the expensive object so the algorithm scales. Random projection (Day 54) approximates distances with a data-oblivious random map — it doesn't touch the kernel. Nyström and Random Fourier Features both approximate the kernel, but from opposite ends: Nyström is data-dependent — it looks at your points and places landmarks where they matter, so it exploits a genuinely low-rank K beautifully and is exact at m = n; RFF is data-oblivious — it draws random cosine features whose expected inner product equals the kernel, which streams and parallelises but can't adapt to structure. Exact low-rank SVD is the gold standard but must build and factor the full matrix. Nyström's genius is buying near-SVD quality for a near-low-rank kernel at a fraction of the cost — the reason it powers sparse Gaussian processes (inducing points), large-scale spectral clustering, and kernel SVMs on data far too big to hold K in memory.

    


    
🎉 Day 55 of MachineLearningFromZero done — making kernels tractable with a handful of landmarks.
The Nyström method rescues kernel machines from the O(n²) memory and O(n³) compute of the full Gram matrix by sampling landmarks: keep only the thin block C of kernel values to m landmark points and the tiny block W among them, and rebuild the entire matrix as K ≈ C W⁺ Cᵀ. It is exact when m = n and its relative Frobenius error decays fast as m grows because a smooth RBF kernel is nearly low-rank — its eigenvalues collapse, so a few well-spread landmarks capture almost all of it. Farthest-point sampling beats uniform random for the same budget by covering the cloud, and a hand-rolled Jacobi eigensolver plus a jittered pseudo-inverse make the tiny W⁺ rock-solid. It sits beside random projections (Day 54) and Random Fourier Features as the toolbox for approximating the expensive linear-algebra object so the method scales. 👉 When n is huge and you need kernels — SVM, Gaussian processes, spectral clustering — reach for Nyström.
