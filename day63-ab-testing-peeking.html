🧪 A/B testing and the peeking problem — the experiment below has no effect whatsoever: both arms are drawn from the same distribution, every time. A fixed-horizon test rejects it about 5% of the time, exactly as advertised. Then we start checking the p-value as the data arrives — the thing every dashboard invites you to do — and the false-positive rate climbs past 20%, 30%, and keeps going, because "stop as soon as p < 0.05" is a rule that eventually stops on almost any null experiment. This page runs the simulation live: a real two-proportion z-test, a real sequential monitoring loop, and three real fixes — Bonferroni on the looks, an alpha-spending boundary (Pocock and O'Brien–Fleming), and an always-valid mixture sequential probability ratio test you may check continuously without penalty. Every number is computed in your browser from simulated coin flips, and the null rate is measured, not quoted.

The test is fine. The stopping rule is the bug.


      
A p-value has a precise meaning, and it is conditional on a design you fixed
      in advance: if there were truly no effect, and you ran this experiment to
      this predetermined sample size, you would see a result this extreme 5% of the
      time. Every word of that matters, and "predetermined" is the one people drop.


      
Because the moment your stopping rule becomes "keep going until p < 0.05", you are no
      longer sampling from that distribution. You are sampling the minimum of a
      random walk over many looks — and the minimum of many draws is far more extreme than any single
      draw.


      

        
With enough looks, a null experiment is guaranteed to
        cross p < 0.05 at some point. Not likely — guaranteed, in the limit. The p-value walk is
        recurrent; it will visit any threshold eventually. So "we ran it until it was significant"
        does not describe a weak result. It describes no result at all.

      


      
Why dashboards make this the default behaviour

      
Every experimentation tool shows a live p-value and a live "winner" badge. The interface
      invites exactly the behaviour that invalidates it. This is not a knowledge problem — the analyst
      usually knows the rule — it is that stopping early is rewarded: the experiment ends
      sooner, the number looks good, and nobody re-runs it.


      
Fix 1 — decide the sample size first, and honour it

      
Power analysis, fixed horizon, no early stopping. It works, and it is unsatisfying: you must
      wait, and you cannot stop early even when the effect is enormous and obvious. But it is correct,
      and it is the baseline every other method is measured against.


      
Fix 2 — group sequential boundaries

      
If you must look K times, use a threshold that accounts for K. Bonferroni (α/K) is the crude
      version and is over-conservative because the looks are highly correlated — the data at look 5
      contains all the data from look 4.

      
Pocock uses one constant, stricter threshold at every look.
      O'Brien–Fleming spends almost no alpha early and nearly all of it at the end,
      which matches how people actually want to behave: stop early only for something spectacular,
      otherwise run to completion. Both are implemented here and both are measured against the same
      null.


      
Fix 3 — always-valid inference

      
The mixture sequential probability ratio test takes a different route. Instead of a p-value
      whose validity depends on when you stop, it produces a statistic that is a
      martingale under the null. Ville's inequality then bounds the probability that
      it ever exceeds 1/α, over an unbounded number of looks.

      
That is the property you actually wanted all along: you may look continuously, stop whenever
      you like, and the error guarantee holds. The cost is power — for a fixed sample size it is less
      sensitive than the fixed-horizon test, which is the honest price of not having to commit.


      
What the numbers on this page are

      
Both arms are generated from the same Bernoulli rate when lift is 0, using a seeded
      PRNG. So the truth is known: any rejection is a false positive, and the "false positive rate"
      counter is a straight count over 2,000 independent experiments — not a formula, not a citation.
      Set a non-zero lift and the same counters become power instead.


    

  






  

    


      
🔨 Build it yourself


      
1. A generator that knows the truth

      
Simulate rather than analyse. If you generate the data, you know whether an effect exists,
      so every method gets a scoreboard instead of an argument.

      
function trial(rng, p){ return rng() < p ? 1 : 0; }
// lift = 0 -> both arms identical -> every rejection is a FALSE POSITIVE


      
2. The two-proportion z-test, written out

      
function zTest(cA, nA, cB, nB){
  const pA = cA / nA, pB = cB / nB;
  const p  = (cA + cB) / (nA + nB);                 // pooled under H0
  const se = Math.sqrt(p * (1 - p) * (1/nA + 1/nB));
  if (se === 0) return { z: 0, p: 1 };
  const z = (pB - pA) / se;
  return { z: z, p: 2 * (1 - normCdf(Math.abs(z))) };  // two-sided
}


      
3. A normal CDF you can trust

      
You need this and you should not hand-wave it. Abramowitz–Stegun 7.1.26 is accurate to
      ~1e-7, which is far beyond what this needs — and the page checks it against known values.

      
function erf(x){
  const s = x < 0 ? -1 : 1; x = Math.abs(x);
  const t = 1 / (1 + 0.3275911 * x);
  const y = 1 - ((((1.061405429*t - 1.453152027)*t) + 1.421413741)*t - 0.284496736)*t*t
              * Math.exp(-x*x) - 0;                  // see the file for the exact form
  return s * y;
}
const normCdf = x => 0.5 * (1 + erf(x / Math.SQRT2));


      
4. The peeking loop — the whole problem, in six lines

      
function runPeeking(rng, p0, lift, n, looks, alpha){
  let cA = 0, cB = 0;
  const step = Math.floor(n / looks);
  for (let k = 1; k <= looks; k++){
    for (let i = 0; i < step; i++){ cA += trial(rng, p0); cB += trial(rng, p0 + lift); }
    if (zTest(cA, k*step, cB, k*step).p < alpha) return true;   // STOP AND DECLARE
  }
  return false;
}

      
Run that with lift = 0 and count how often it returns true. It is not 5%.


      
5. Boundaries: spend the alpha deliberately

      
// Pocock: one constant threshold across all K looks
const pocockZ = K => 1.96 + 0.62 * Math.log(K);        // practical approximation

// O'Brien-Fleming: very strict early, near-nominal at the end
const obfZ = (k, K) => 2.96 / Math.sqrt(k / K);

      
State that these are approximations of the exact boundaries. The page does — a number whose
      provenance you hide is a number the reader cannot check.


      
6. Always-valid: a martingale, not a p-value

      
// mixture SPRT: likelihood ratio mixed over a prior on the effect size.
// Under H0 this is a martingale starting at 1, so Ville's inequality gives
// P(ever exceeding 1/alpha) <= alpha - for UNBOUNDED continuous monitoring.
function msprtStat(cA, nA, cB, nB, tau){
  const pooled = (cA + cB) / (nA + nB);
  const v = pooled * (1 - pooled) * (1/nA + 1/nB);
  if (!(v > 0)) return 0;
  const delta = cB/nB - cA/nA;
  const r = Math.sqrt(v / (v + tau*tau)) *
            Math.exp(tau*tau * delta*delta / (2 * v * (v + tau*tau)));
  return r;                                            // reject when r > 1/alpha
}


      
7. Measure all four against the same null

      
Same seed, same data, four decision rules. That is the only fair comparison, and it is what
      the SIMULATE tab runs — 2,000 experiments, false-positive rate counted, not derived.
