🧮 The Theil–Sen estimator — the robust line you can compute with nothing but a median. Ordinary least squares picks the slope that minimises the sum of squared residuals, so a single far-off point — whose squared error is enormous — pivots the whole line toward itself; its breakdown point is zero. Theil–Sen throws that machinery away for something almost startlingly simple: take every pair of points, compute the slope of the line through that pair, and let the median of all those pairwise slopes be your slope. The intercept is then just median(yᵢ − m·xᵢ). That is the entire estimator — no loss function, no iteration, no gradient, no threshold to tune. Why it works is the whole point: an outlier corrupts only the pairs it belongs to, and those corrupted pairs produce extreme slopes that land in the tails of the distribution — where the median simply steps over them. You have to contaminate nearly 29% of the data before the median slope itself is pulled off, versus one bad point for OLS. Everything below runs live in your browser — scatter points and drag them or click to add outliers, watch the median-of-slopes line hold the truth while least-squares is dragged away, see the full histogram of pairwise slopes with its median vs mean, and pull an outlier cluster to feel the two philosophies diverge.

Least squares has no defence against a single bad point. Because it minimises the sum of squared residuals, one lone outlier can pivot the entire fitted line toward itself — its breakdown point is zero. Theil–Sen answers with the humblest robust idea in statistics: the slope between two points is a slope estimate, so compute it for all n(n−1)/2 pairs and take the median. A median cannot be moved by a minority of extreme values, and an outlier only spoils the pairs it touches — a minority — so the corrupted pairwise slopes fall harmlessly into the tails while the median holds. The intercept follows the same recipe: median(yᵢ − m·xᵢ). No squared error, no iteration, no tuning constant, and no random sampling — the estimate is exact and deterministic. 🔨 Build it yourself

    
Theil–Sen is arguably the least code of any robust regressor — the exact routine the LOOK tab runs, no scikit-learn black box. Below is the runnable core: the slope through a pair of points, the slope over every pair, the median that makes it robust, the two-line estimator itself (median slope, then median intercept), the breakdown-point argument, and the standard tools. Every line the LOOK tab draws comes from these snippets.

    
    
      
  1. 
        
    1
    The slope through a pair of points
    
        
    The whole estimator is built on the most elementary fact in coordinate geometry: two points define a line, and its slope is rise over run. Each pair of your data points is therefore a tiny, independent slope estimate. (A pair sharing an x-value is a vertical line with undefined slope — just skip it.)
    
        
    function pairSlope(p, q) {
  const dx = q.x - p.x;
  if (Math.abs(dx) < 1e-9) return null;   // same x → undefined slope, skip
  return (q.y - p.y) / dx;                // rise over run
}
    
      
    2. 
      
  2. 
        
    2
    Every pairwise slope
    
        
    Now take that slope for all n(n−1)/2 unordered pairs. This is the one price Theil–Sen pays — it is O(n²) in both time and memory. But the payoff is that a single outlier can only ever spoil the n−1 pairs that include it, a vanishing fraction of the whole for large n, so most of these slopes come from clean pair-of-inliers and cluster tightly around the truth.
    
        
    function allPairSlopes(pts) {
  const slopes = [];
  for (let i = 0; i < pts.length; i++)
    for (let j = i + 1; j < pts.length; j++) {   // each unordered pair once
      const s = pairSlope(pts[i], pts[j]);
      if (s !== null) slopes.push(s);
    }
  return slopes;                                  // n(n−1)/2 of them
}

    The median — the source of the robustness
    
        
    This one function is why Theil–Sen shrugs off outliers where the mean (and hence least squares) does not. The median depends only on the rank of a value, not its magnitude — you can send half-minus-one of the numbers to infinity and it does not move. Take the median of a set of slopes and the extreme, outlier-born slopes in the tails are stepped over entirely.
    
        
    function median(a) {
  if (!a.length) return 0;
  const s = a.slice().sort((x, y) => x - y);      // rank the values
  const n = s.length;
  return n % 2 ? s[(n - 1) / 2]                    // odd → middle element
               : 0.5 * (s[n/2 - 1] + s[n/2]);     // even → mean of middle two
}

    The Theil–Sen estimator — two medians
    
        
    That is the entire algorithm. The slope is the median of all pairwise slopes; the intercept is the median of yᵢ − m·xᵢ — the value that makes half the points sit above the line and half below at that slope. No loss function, no iterations, no learning rate, no threshold, no randomness. The result is exact and deterministic: run it twice on the same data, get the same line to the last bit.
    
        
    function theilSen(pts) {
  const m = median(allPairSlopes(pts));            // slope = median of slopes
  const intercepts = pts.map(p => p.y - m * p.x);  // b that centres each point
  const b = median(intercepts);                    // intercept = their median
  return { m, b };                                 // y = m·x + b, done
}

    The breakdown point — why ~29%
    
        
    The median of a list breaks at 50% contamination. Theil–Sen's slope is a median of pairs, and a fraction ε of bad points makes a pair bad with probability 1−(1−ε)². Solve for when that reaches half — the point where corrupted pairs could dominate — and you get ε = 1 − 1/√2 ≈ 0.293. So Theil–Sen tolerates just under 29.3% of arbitrary contamination, a colossal jump from OLS's 0%, while staying a simple closed formula.
    
        
    # the breakdown-point algebra (why 29.3%, not 50%)
# a pair is "clean" only if BOTH its points are inliers:
#   P(clean pair) = (1 - eps)^2
# the median of slopes tips once bad pairs reach half:
#   (1 - eps)^2 = 1/2   ->   eps = 1 - 1/sqrt(2) = 0.2929...
# OLS breakdown = 0 (one point);  Theil-Sen = 29.3%;  RANSAC/LMS = up to 50%

    In practice — the standard tools
    
        
    You will rarely hand-roll it. SciPy's theilslopes returns the median slope, intercept, and a confidence interval for the slope in one call. scikit-learn's TheilSenRegressor generalises the idea to multiple features (it takes the spatial median over random subsets of features+1 points, since exhaustive pairs explode in high dimensions) and drops into any pipeline with the usual fit/predict.
    
        
    # SciPy — slope, intercept, and a slope confidence interval
from scipy.stats import theilslopes
slope, intercept, lo, hi = theilslopes(y, x, 0.95)

# scikit-learn — multivariate Theil-Sen (subsamples in high-D)
from sklearn.linear_model import TheilSenRegressor
ts = TheilSenRegressor(random_state=0).fit(X, y)
robust_line = (ts.coef_, ts.intercept_)

The trade is how much contamination you expect and how much you are willing to configure. OLS is optimal on clean Gaussian noise and useless the instant one high-leverage point appears. Huber (Day 52) keeps least-squares' smoothness but grades big residuals down to linear, tolerating a few mild outliers while still bending toward a gross one. Theil–Sen is the elegant middle: no loss, no iteration, no threshold — just the median of every pairwise slope — deterministic and robust to nearly 29% contamination, at an O(n²) cost that is trivial for the small, low-dimensional problems it shines on (it is a favourite for trend estimation in climate and econometrics). RANSAC (Day 51) makes the opposite bet: throw points away and sample for a consensus, tolerating well past half the data as garbage — but it is random, needs a threshold, and is not smooth. LAD / L1 minimises absolute error — robust to vertical outliers but, like Huber and OLS, defenceless against a high-leverage point in x. Theil–Sen's genius is that it buys real, tuning-free robustness with nothing more exotic than the median — the same reason it, like all these methods, still bends to a point placed far out in x.

    


    
🎉 Day 53 of MachineLearningFromZero done — the robust line you fit with a median.
The Theil–Sen estimator replaces least-squares' fragile sum-of-squares with the humblest robust idea in statistics: the slope between two points is a slope estimate, so compute it for all n(n−1)/2 pairs and take the median; the intercept is median(yᵢ − m·xᵢ). Because the median depends only on rank and an outlier corrupts only the minority of pairs it touches — pairs whose slopes fall harmlessly into the tails — the fit is unmoved until nearly 29.3% of the data is contaminated, versus a single point for OLS, and it needs no loss function, no iteration, no threshold, and no randomness: the estimate is exact and deterministic. Its one cost is the O(n²) sweep over pairs, cheap for the small, low-dimensional trend problems where it is beloved, and generalised by scikit-learn to higher dimensions via subsampling. That places Theil–Sen between the smooth all-points estimators — OLS and Huber (Day 52) — and the sample-and-vote world of RANSAC (Day 51): more robust and simpler to use than Huber, more deterministic and tuning-free than RANSAC, but still bendable by a high-leverage point far out in x. 👉 When your data is one- or low-dimensional, you expect up to a quarter of it to be junk, and you want a robust slope with literally nothing to tune, reach for Theil–Sen.
