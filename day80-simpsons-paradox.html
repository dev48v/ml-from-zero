🎯 Simpson's paradox in model evaluation — model A is better than model B on every subgroup, and model B wins the leaderboard. Nothing here is sampled and no ranking is decided by a float: every accuracy is an exact rational over declared integer counts, and every winner is settled by BigInt cross-multiplication, so a reversal is proved rather than observed through rounding. 🔴 On the declared three-slice benchmark A leads 96.0 / 60.0 / 50.0 against 88.0 / 50.0 / 40.0 — ahead in all three — and still loses the pooled number 57.60% to 79.06%, a 21.5-point defeat assembled entirely out of victories. 🔴 Macro and micro disagree in sign in 100% of the 9,510 reversals found: micro is the per-slice rates averaged with the slice sizes as weights, macro is the same average with the weights thrown away, and per-slice dominance forces macro to agree with the slices while leaving micro free to say the opposite. 🔴 The driver is neither size nor difficulty on its own, it is the mixture: an exhaustive sweep of 3,748,096 two-group tables shows the reversal needs just 9 observations at its smallest, can reach a 55.6-point pooled reversal, and can hold a 37.5-point lead in every single group and still lose. 🔴 The negative result is the one to keep: force the two models onto the same per-group sample sizes and the reversal count over that same sweep is exactly 0 of 14,400 — 0 of 32,544 if you make only the proportions match. Equal total sample size is not enough; 502 reversals survive that.

Two models, one benchmark, three slices. Nobody has cheated and nothing is noisy. Both models were scored on the same task, both scoreboards are exact integer counts, and every per-slice comparison goes the same way. The only thing that differs between them is how much of each slice each model was scored on — and that alone flips the ranking.

Where the two models actually got measured

This is the whole story in one table. A was scored mostly on the slice it is worst at; B was scored mostly on the slice both are best at. Neither model chose that — it is a property of the evaluation set, not of the weights — and a pooled scalar reported without these shares cannot be distinguished from a genuine quality difference.

1. Micro is a weighted macro — the identity everything rests on

Pooled accuracy is not a different kind of quantity from the per-slice rates. It is exactly their mean, weighted by slice size: Σcg / Σng = Σ(ng/N)·(cg/ng). The table computes both sides by two different routes and compares them as exact rationals, not to a tolerance. Macro is the same sum with every weight replaced by 1/G. So the two metrics differ in exactly one place — the weights — and the entire paradox lives in that difference.

2. The smallest reversal in existence, found by sweeping the space

Every two-group table with per-cell sample size from 1 to — was swept: — tables. — of them put A strictly ahead in both groups, and — of those reverse once pooled. The minimum total sample across all of them is — observations, reached by exactly — tables — two of them plus their group-relabellings. You do not need a large benchmark or a subtle effect: four cells and nine data points are enough to rank two models backwards.

4. The negative result: it cannot happen on a shared mixture

🔴 Re-run the same sweep with the group sizes forced equal across the two models and the reversal count is 0 — not rare, not small: absent. The reason is one line. With the weights fixed, pooled accuracy is a weighted mean using the same non-negative weights for both models, a weighted mean is monotone in its inputs, so per-group dominance is inherited by the pooled number. Matching only the proportions is already enough — also 0, over a strictly larger family. Matching only the totals is not: 502 reversals survive that, the smallest at 10 observations. The defence is a shared slice mixture, not a shared sample size.

5. Controls, so that none of the zeros above is vacuous

A sweep that finds 0 reversals proves nothing unless the same machinery finds them when it should, so every row prints the number of comparisons behind its count: a 0 from an impossibility is then distinguishable from a 0 from an empty search. The one-group row is the degenerate control — with a single group the pooled number is the group, so a reversal would be a contradiction, and the sweep duly reports none over — comparisons. The pruning audit re-runs a smaller bound with no precondition filter at all, to show the fast sweep is not skipping candidates.

What this covers, and what it does not

One metric — accuracy as correct/total — and two models compared head to head. The sweep runs over two groups with per-cell sample sizes up to —, so the minimum reported here is exact for two groups and not a claim about any other number of them. A third slice does not make it cheaper — each extra group adds two more cells that must each be strictly won, and the smallest three-group reversal costs 13 observations against nine. There is no statistical test anywhere on this page: nothing is sampled, every count is declared, and every comparison is an exact rational, so a p-value would be a category error rather than a missing feature. And this page does not tell you which number is right. Macro and micro answer different questions, and choosing between them needs a deployment mixture that a benchmark does not carry. What it does say is narrower and harder to argue with: a single pooled scalar, published without the slice sizes that produced it, is not a ranking anybody can check.

How it works

// micro (pooled) is a weighted macro. Same mean, different weights.
//   micro(M) = sum_g c_g / sum_g n_g = sum_g (n_g/N) * (c_g/n_g)
//   macro(M) = (1/G) * sum_g (c_g/n_g)

// so when both models carry the SAME weights w_g:
//   acc_A(g) > acc_B(g) for every g   =>   sum w_g acc_A(g) > sum w_g acc_B(g)
// a weighted mean with fixed non-negative weights is monotone in its inputs.
// The reversal REQUIRES w_A != w_B. Everything else is bookkeeping.

// every winner is decided by cross-multiplication, never by a float
const rcmp = (a, b) => { const l = a.n * b.d, r = b.n * a.d;
                         return l < r ? -1 : l > r ? 1 : 0; };

// the sweep: all (c,n) cells with 1 <= n <= NMAX and 0 <= c <= n, four cells
// deep. Pruning is by the reversal's own precondition (per-group dominance), so
// it can only drop tables that could not have qualified - and that claim is
// audited against a full, unfiltered four-deep enumeration at a smaller bound.

Self-check running…

Runs on load. Several are controls: an impossibility claim is worth nothing without a nearby search that does find instances, so every 0 is printed next to the number of comparisons that produced it, every reported instance is re-verified on both halves of the claim separately, and the pruned sweep is audited against a full enumeration.
