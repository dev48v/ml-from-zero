🎯 Threshold transfer — you tune a decision threshold on validation to hit “precision at least 90%”, then deploy it somewhere the validation set was not. Nothing here is sampled and no rate is a float: the score axis is 201 bins of declared integer weights, all 201 thresholds are enumerated, and every rate is an exact rational compared by BigInt cross-multiplication, so an argmax is never decided by rounding. 🔴 Drop the prevalence from 10% to 2% and that threshold delivers 63.5% precision instead of 90.4% — while its TPR and FPR stay bit-identical, the same reduced fractions 22663/29409 and 21043/499953. The model did not change and the scores did not change. The number just stopped meaning what it meant. 🔴 Two of the five tuning rules pick a threshold that survives a prevalence shift completely unchanged, and they are exactly the two defined only from class-conditional rates — Youden's J stays at 100 and recall≥0.90 stays at 98, while maximise-F1 moves 127→146 and precision≥0.90 moves 148→169. 🔴 And re-tuning is not the escape it looks like: re-running precision≥0.90 on the shifted world does restore 90% precision, at a recall of 1.90%. You meet the target by answering almost nothing. 🔴 The last one is the practical problem: the only quantity you can monitor without labels cannot tell the two shifts apart. A prevalence shift and a score shift are constructed here with the exactly equal positive rate 780643/49995300, and precision of 63.46% against 2.23% — a 28.5× gap behind an identical dashboard.

Four worlds, one model. The classifier is never retrained and its scores are never recomputed for a given input. Only the population changes: how many positives there are (prevalence shift), where the negatives land on the score axis (score shift), or both. Everything below is a consequence of moving the population, not of moving the model.

1. TPR and FPR do not know what the prevalence is

One threshold (bin 120), six prevalences from 0.1% to 90%. The two class-conditional rates are printed as reduced fractions and they are the same string in every row, because each is conditioned on the class and the prevalence divides out of both. Precision over the same six rows goes from 0.0180 to 0.9940. This is not a subtle effect that needs a confidence interval — it is an algebraic identity on one side and a fifty-fold swing on the other, and it is the whole reason a transferred threshold misbehaves.

2. Which rules pick a portable threshold

Re-running each rule on each world, and reading off where it lands. Under a pure prevalence shift the two rules whose definitions mention only TPR and FPR — Youden's J and recall≥0.90 — return exactly the threshold they returned on the source, while the two that mention precision or F1 move. That is not a coincidence to be checked empirically; it follows from the identity above. Scope: recall≥0.90 is also unmoved by the score shift here, but only because this shift moves the negatives. Recall does not look at negatives. Move the positives instead and it moves like everything else.

3. Re-tuning meets the target and hollows out the model

🔴 Re-running precision≥0.90 on each world does restore the number: 0.9088, 0.9041, 0.9022. The recall behind it goes 0.4955 → 0.2412 → 0.2773 → 0.0190. In the last world the threshold that satisfies the contract fires on 1.9% of the positives. A precision target is a promise about the answers you give, and it can always be kept by giving fewer — so a monitor that watches only precision will report a healthy system right up to the point where the system is not answering.

4. The label-free monitor cannot tell the two apart

🔴 In production you usually have no labels, so the one thing you can watch is how often the model says yes. Take the source-tuned threshold and two different worlds: a prevalence shift to 2%, and a score shift at prevalence —. The prevalence for the second was solved from the rational equation rate = π·TPR + (1−π)·FPR, so the positive rate is not close, it is the identical fraction. Precision is 63.46% in one and 2.23% in the other. Every dashboard that watches the firing rate shows a flat line across both.

What this covers, and what it does not

One score axis discretised into 201 bins; one shift direction (the negatives move up 12 bins, the positives never move); one pair of class-conditional shapes; five tuning rules; four metrics. There is no cost matrix, so “which threshold is right” is never answered here — only which one is stable. There is no calibration model and no recalibration method: the point is what breaks, not how to fix it. And there are no confidence intervals anywhere on this page, because nothing is sampled — every number is an exact rational over a declared integer population, so an interval would be a decoration rather than a statement.

How it works

// a virtual population of q*WP*WN, so all four confusion cells are integers
TP = p * Sp * WN;          FP = (q - p) * Sn * WP;
FN = p * (WP - Sp) * WN;   TN = (q - p) * (WN - Sn) * WP;

// TPR = TP/(TP+FN) = (p*Sp*WN) / (p*Sp*WN + p*(WP-Sp)*WN) = Sp/WP
//   -> p and q cancel. That one line is the whole page.

// and the argmax is decided exactly, never by comparing two floats
const rcmp = (a, b) => { const l = a.n * b.d, r = b.n * a.d;
                         return l < r ? -1 : l > r ? 1 : 0; };

Self-check

Runs on load. Several are controls: an invariance claim is worth nothing without the quantities that do move, so the checks that TPR is constant sit next to checks that precision is not, and the ambiguity construction is verified as an exact equality rather than a rounding.
