MachineLearningFromZero · Day 59

🎲 The Hidden Markov Model — the first model in this series where the thing you want to know is never in the data. Everything so far mapped a row of features to an answer: Logistic Regression (D2) read a feature vector and returned a class, K-Means (D4) grouped independent points, even GMM/EM (D22) treated every sample as a fresh draw with no memory of the last one. An HMM assumes the opposite: your observations were produced by a hidden sequence of states that you cannot see, that evolves in time, and where what happens next depends on where you are now. A casino quietly swaps a fair die for a loaded one and swaps back; you only ever see the rolls. A phone hears an acoustic waveform; the words are hidden. A gene sequencer reads bases; whether you are inside a coding region is hidden. An HMM is exactly three tables — π (where the chain starts), A (how hidden states follow each other), B (what each hidden state tends to emit) — plus two independence assumptions that make everything computable: the Markov property (the next state depends only on the current one, not the whole past) and output independence (an observation depends only on the state that emitted it). Those two assumptions buy you an enormous prize. The honest question "how likely is this observation sequence?" means summing over every hidden path — Nᵀ of them, which is 1030 paths for 100 steps of a 2-state chain — and yet the forward algorithm answers it exactly in O(T·N²) by refusing to re-walk shared prefixes, carrying one number αₜ(i) per state per timestep. Swap that sum for a max and keep backpointers and you get Viterbi, which returns the single most likely hidden path exactly. Run forward and backward, turn the products into expected counts, and re-estimate the three tables: that is Baum-Welch, the EM algorithm (D22's engine) applied to sequences — it learns π, A, B from observations alone, with no labelled hidden states at all, and its likelihood is mathematically guaranteed never to go down. Everything below runs live in your browser with no libraries: watch Viterbi recover a hidden FAIR/LOADED track from nothing but dice rolls, step through the forward trellis while the page simultaneously enumerates all Nᵀ paths by brute force and proves the two agree to 12 decimal places, and start Baum-Welch from deliberately wrong parameters and watch the log-likelihood climb, monotonically, to the true model's line. (Everything here is the real algorithm — exact forward with scaling, exact log-space Viterbi with backpointers, exact forward-backward posteriors and exact Baum-Welch re-estimation. Nothing is approximated or faked, and the brute-force check inside the page is your proof.)

You see the emissions. You want the states. An HMM is π (start), A (state → state), B (state → observation). Three questions follow, and each has an exact dynamic-programming answer: how likely is this sequence? — the forward algorithm, O(T·N²) instead of Nᵀ; what hidden path best explains it? — Viterbi, the same recursion with max replacing Σ plus backpointers; what are π, A, B if nobody told me? — Baum-Welch, EM driven by forward-backward expected counts. All three are implemented from scratch below and run live.

🔨 Build it yourself

    
An HMM is three tables and four routines. Below is the exact runnable core the LOOK tab uses — sampling, the scaled forward pass, the matching backward pass, the posteriors, log-space Viterbi, one Baum-Welch iteration, and the brute-force enumeration you check it against. Roughly 90 lines of arithmetic, no dependencies.

    
    

      
  1. 
        
    1
    The model is three tables — and one sampler
    
        
    An HMM λ = (π, A, B) is nothing but three row-stochastic tables: π[i] = probability the chain starts in state i; A[i][j] = probability of moving from i to j; B[i][k] = probability that state i emits symbol k. Sampling from it is the clearest way to see what the model believes: pick a start state, emit, hop, emit, hop. Keep the hidden states so you can score a decoder against them later — but never let the algorithms see them.
    
        
    // λ = (π, A, B). Rows of every table sum to 1.
const model = {
  states: ["FAIR", "LOADED"],
  pi: [0.85, 0.15],
  A:  [[0.95, 0.05],      // FAIR   -> FAIR / LOADED
       [0.10, 0.90]],     // LOADED -> FAIR / LOADED
  B:  [[1/6,1/6,1/6,1/6,1/6,1/6],            // FAIR die
       [0.10,0.10,0.10,0.10,0.10,0.50]]      // LOADED die: sixes
};

function pick(rng, probs) {              // sample an index from a row
  let u = rng(), acc = 0;
  for (let i = 0; i < probs.length; i++) { acc += probs[i]; if (u < acc) return i; }
  return probs.length - 1;
}

function sample(model, T, rng) {
  const { pi, A, B } = model, states = [], obs = [];
  let s = pick(rng, pi);
  for (let t = 0; t < T; t++) {
    states.push(s);                      // the HIDDEN truth
    obs.push(pick(rng, B[s]));           // the only thing you get to see
    if (t < T - 1) s = pick(rng, A[s]);  // hop
  }
  return { states, obs };
}

    2
    The honest but hopeless way — enumerate every path
    
        
    The definition of P(O|λ) is a sum over every hidden path: Σ_q P(O,q|λ). Written literally that is Nᵀ terms. It is worth coding once, because it is the ground truth everything else is checked against — and because watching it die at T=25 is the most persuasive argument for dynamic programming you will ever get. Keep it for tests only.
    
        
    // N^T paths. Correct, and unusable past ~T=20.
function brute(o, pi, A, B) {
  const T = o.length, N = pi.length, cur = new Array(T);
  let total = 0, bestP = -Infinity, bestPath = null;
  (function rec(t) {
    if (t === T) {
      let p = pi[cur[0]] * B[cur[0]][o[0]];
      for (let s = 1; s < T; s++) p *= A[cur[s-1]][cur[s]] * B[cur[s]][o[s]];
      total += p;                                   // the SUM  -> forward
      if (p > bestP) { bestP = p; bestPath = cur.slice(); }   // the MAX -> Viterbi
      return;
    }
    for (let i = 0; i < N; i++) { cur[t] = i; rec(t + 1); }
  })(0);
  return { logLik: Math.log(total), bestPath, bestLogProb: Math.log(bestP) };
}
// T=9, N=2  ->      512 paths   (instant)
// T=40, N=2  -> 1.1e12 paths    (hours)
// T=100,N=2  -> 1.3e30 paths    (never)

    3
    The forward algorithm, with scaling
    
        
    All those paths share prefixes, so stop re-walking them. αₜ(i) = P(o₀..oₜ, qₜ=i) can be built from the previous column alone: αₜ(j) = [Σᵢ αₜ₋₁(i)·A[i][j]] · B[j][oₜ]. That is T·N² multiplications total. One practical wrinkle matters more than it sounds: α shrinks by a factor of roughly P(obs) every step and underflows to exactly 0 within a few hundred timesteps, so normalise each column, keep the normaliser cₜ, and recover log P(O) = Σ log cₜ.
    
        
    // O(T*N^2), numerically safe for any T.
function forward(o, pi, A, B) {
  const T = o.length, N = pi.length, alpha = [], c = [];
  const a0 = new Array(N); let s = 0;
  for (let i = 0; i < N; i++) { a0[i] = pi[i] * B[i][o[0]]; s += a0[i]; }
  c.push(s); for (let i = 0; i < N; i++) a0[i] /= s;      // normalise column 0
  alpha.push(a0);
  for (let t = 1; t < T; t++) {
    const at = new Array(N).fill(0); let st = 0;
    for (let j = 0; j < N; j++) {
      let sum = 0;
      for (let i = 0; i < N; i++) sum += alpha[t-1][i] * A[i][j];   // hop
      at[j] = sum * B[j][o[t]];                                     // emit
      st += at[j];
    }
    c.push(st); for (let j = 0; j < N; j++) at[j] /= st;   // normalise, remember cₜ
    alpha.push(at);
  }
  let ll = 0; for (const x of c) ll += Math.log(x);        // log P(O|λ) = Σ log cₜ
  return { alpha, c, logLik: ll };
}
// alpha[t][i] is now P(state i at t | o_0..o_t) — the FILTERED belief.

  4. 
        
    4
    The backward pass — and the posteriors it unlocks
    
        
    Forward knows the past. βₜ(i) = P(oₜ₊₁..o_{T−1} | qₜ=i) knows the future, computed by the same recursion run right-to-left. Multiply them and you get the smoothed posterior γₜ(i): the probability of being in state i at time t given the entire sequence, including everything that happened afterwards. Reuse the forward pass's cₜ as backward's scale factors and the bookkeeping collapses to the two clean lines below.
    
        
    function backward(o, A, B, c) {          // reuse forward's scale factors
  const T = o.length, N = A.length;
  const beta = Array.from({length:T}, () => new Array(N).fill(0));
  for (let i = 0; i < N; i++) beta[T-1][i] = 1 / c[T-1];
  for (let t = T-2; t >= 0; t--)
    for (let i = 0; i < N; i++) {
      let s = 0;
      for (let j = 0; j < N; j++) s += A[i][j] * B[j][o[t+1]] * beta[t+1][j];
      beta[t][i] = s / c[t];
    }
  return beta;
}

function posteriors(o, pi, A, B) {
  const F = forward(o, pi, A, B), be = backward(o, A, B, F.c);
  const T = o.length, N = pi.length;
  // γₜ(i) = P(state i at t | the WHOLE sequence)
  const gamma = Array.from({length:T}, (_, t) =>
    Array.from({length:N}, (_, i) => F.alpha[t][i] * be[t][i] * F.c[t]));
  // ξₜ(i,j) = P(i at t AND j at t+1 | the whole sequence)
  const xi = Array.from({length:T-1}, (_, t) =>
    Array.from({length:N}, (_, i) =>
      Array.from({length:N}, (_, j) =>
        F.alpha[t][i] * A[i][j] * B[j][o[t+1]] * be[t+1][j])));
  return { gamma, xi, logLik: F.logLik, alpha: F.alpha, c: F.c };
}
// Σᵢ γₜ(i) = 1 for every t.  Σⱼ ξₜ(i,j) = γₜ(i).  Both are asserted in the tests.

    Viterbi — the same recursion with max, plus backpointers
    
        
    Replace the sum with a maximum and you stop asking "how much total probability reaches this cell?" and start asking "what is the best single path that reaches it?". Record which predecessor won (ψ), and when you reach the end, walk the winners backwards to reconstruct the path. Do it all in log space: multiplying hundreds of probabilities underflows, adding hundreds of logs does not, and because log is monotone the argmax is untouched.
    
        
    function viterbi(o, pi, A, B) {
  const T = o.length, N = pi.length, L = x => x > 0 ? Math.log(x) : -Infinity;
  const d   = Array.from({length:T}, () => new Array(N).fill(-Infinity)); // best log-prob
  const psi = Array.from({length:T}, () => new Array(N).fill(0));         // backpointer
  for (let i = 0; i < N; i++) d[0][i] = L(pi[i]) + L(B[i][o[0]]);
  for (let t = 1; t < T; t++)
    for (let j = 0; j < N; j++) {
      let best = -Infinity, arg = 0;
      for (let i = 0; i < N; i++) {          // MAX where forward had a SUM
        const v = d[t-1][i] + L(A[i][j]);
        if (v > best) { best = v; arg = i; }
      }
      d[t][j] = best + L(B[j][o[t]]);
      psi[t][j] = arg;                        // remember who won
    }
  let best = -Infinity, arg = 0;
  for (let i = 0; i < N; i++) if (d[T-1][i] > best) { best = d[T-1][i]; arg = i; }
  const path = new Array(T); path[T-1] = arg;
  for (let t = T-2; t >= 0; t--) path[t] = psi[t+1][path[t+1]];   // walk back
  return { path, logProb: best };
}

    Baum-Welch — one EM iteration
    
        
    If you could see the hidden states, fitting the model would be counting: how often did state i start a sequence, how often did i lead to j, how often did i emit symbol k. You cannot see them — so use expected counts instead. The E-step is exactly the forward-backward pass (γ and ξ ARE those expected counts); the M-step normalises them into new tables. Repeat. The likelihood provably never decreases.
    
        
    function bwStep(o, pi, A, B, M) {              // M = number of symbols
  const N = pi.length, T = o.length;
  const { gamma, xi, logLik } = posteriors(o, pi, A, B);   // ---- E-step ----

  const npi = gamma[0].slice();                            // ---- M-step ----

  const nA = Array.from({length:N}, () => new Array(N).fill(0));
  for (let i = 0; i < N; i++) {
    let den = 0; for (let t = 0; t < T-1; t++) den += gamma[t][i];   // times in i
    for (let j = 0; j < N; j++) {
      let num = 0; for (let t = 0; t < T-1; t++) num += xi[t][i][j]; // i -> j
      nA[i][j] = den > 0 ? num / den : 1 / N;
    }
  }

  const nB = Array.from({length:N}, () => new Array(M).fill(0));
  for (let i = 0; i < N; i++) {
    let den = 0; for (let t = 0; t < T; t++) den += gamma[t][i];
    for (let k = 0; k < M; k++) {
      let num = 0; for (let t = 0; t < T; t++) if (o[t] === k) num += gamma[t][i];
      nB[i][k] = den > 0 ? num / den : 1 / M;
    }
  }
  return { pi: npi, A: nA, B: nB, logLik };   // logLik is BEFORE this update
}

let pi = randomRow(N), A = randomRows(N,N), B = randomRows(N,M);
for (let it = 0; it < 200; it++) {
  const st = bwStep(obs, pi, A, B, M);
  pi = st.pi; A = st.A; B = st.B;       // st.logLik never decreases
}

    Prove it — check the DP against brute force
    
        
    Dynamic programming is easy to write and easy to get subtly wrong; an off-by-one in the backward recursion or a misplaced scale factor still produces plausible-looking numbers. The cure is a test with an independent baseline. For small T the brute-force enumeration is that baseline — it is the definition, coded literally — so assert that forward matches its sum, Viterbi matches its argmax, and the posteriors match its marginals. This exact suite runs on three different HMMs and passes 38/38.
    
        
    const T = 9;                                  // 2^9 = 512 paths — enumerable
const { obs } = sample(model, T, rng);
const P  = posteriors(obs, pi, A, B);
const V  = viterbi(obs, pi, A, B);
const BF = brute(obs, pi, A, B);              // the definition, literally

assert(Math.abs(P.logLik   - BF.logLik)      < 1e-10);  // forward == Σ over paths
assert(Math.abs(V.logProb  - BF.bestLogProb) < 1e-10);  // viterbi == max over paths
assert(V.path.join() === BF.bestPath.join());           // and the SAME path
assert(maxAbs(P.gamma, BF.gamma) < 1e-12);              // γ == exact marginals
assert(P.gamma.every(r => Math.abs(sum(r) - 1) < 1e-12));

// EM's theorem, checked empirically over 6 random inits x 150 iterations:
let prev = -Infinity;
for (const ll of logLikHistory) { assert(ll >= prev - 1e-9); prev = ll; }

    In practice — the standard tools and the traps
    
        
    In Python you would reach for hmmlearn (discrete CategoricalHMM, continuous GaussianHMM) or pomegranate. Three traps catch everyone: EM is local, so use many random restarts and keep the best likelihood; probabilities that hit exactly zero can never come back, so smooth your counts; and the number of hidden states is a modelling choice you must select, typically by BIC or held-out likelihood, not something EM discovers for you.
    
        
    from hmmlearn.hmm import CategoricalHMM
import numpy as np

X = obs.reshape(-1, 1)                 # (T, 1) integer symbols
lengths = [len(obs)]                   # concatenate many sequences here

best = None
for seed in range(10):                                   # EM is LOCAL — restart
    m = CategoricalHMM(n_components=2, n_iter=200, tol=1e-4,
                       random_state=seed, init_params="ste")
    m.fit(X, lengths)
    if best is None or m.score(X, lengths) > best.score(X, lengths):
        best = m

print(best.score(X, lengths))          # log P(O | λ)  — the forward algorithm
print(best.predict(X, lengths))        # the Viterbi path
print(best.predict_proba(X, lengths))  # the γ posteriors
print(best.transmat_, best.emissionprob_)

# choose n_components by BIC / held-out likelihood, never by "it fit better"
# smooth: emissionprob_ = (counts + 1e-3); rows renormalised
# state LABELS are arbitrary — state 0 of a refit may be state 1 of this one

🧭 The three questions an HMM answers — and the algorithm for each

      

        
QuestionNameRecursionCostWhat you get

        
How likely is this sequence?Forward (evaluation)αₜ(j) = [Σᵢ αₜ₋₁(i)Aᵢⱼ]·Bⱼ(oₜ)O(T·N²)log P(O|λ) — a score you can compare across models, use for classification, or maximise

        
Which hidden path explains it?Viterbi (decoding)δₜ(j) = maxᵢ[δₜ₋₁(i)Aᵢⱼ]·Bⱼ(oₜ)O(T·N²)the single most probable state sequence, guaranteed globally consistent

        
What is the state right now?Forward only (filtering)α̂ₜ(i) normalisedO(t·N²)a belief using only the past — the online, real-time answer

        
What was the state back then?Forward-backward (smoothing)γₜ(i) = α̂ₜ(i)β̂ₜ(i)cₜO(T·N²)a per-timestep belief using the whole sequence — sharper, but offline

        
What are π, A, B?Baum-Welch (learning)re-estimate from γ, ξO(I·T·N²)a fitted model from unlabelled sequences; likelihood never decreases

      

      
Viterbi and smoothing answer different questions and can disagree: γ picks the best state at each timestep independently, so stitching those choices together can produce a path the model considers impossible (a transition with probability 0). Viterbi's answer is always a legal path. Use Viterbi when the whole sequence must be coherent (speech, tagging, gene annotation); use γ when you want per-timestep confidence.

The HMM is not obsolete. It stays the right answer when data is scarce, when the latent states must be interpretable ("regime 1 is a bull market", "state 3 is a coding region"), when you need calibrated probabilities rather than a point prediction, and when you must train with no labels at all. Its machinery is also the ancestor of much of modern sequence modelling — the forward pass is the message-passing that reappears in linear-time state-space models like Mamba, and Viterbi still runs inside decoders everywhere.

    


    
🎉 Day 59 of MachineLearningFromZero done — the model that infers a hidden story from the evidence it leaves behind.
A Hidden Markov Model is three tables — π, A, B — plus two assumptions (Markov transitions, output independence) that turn an impossible sum over Nᵀ paths into three exact O(T·N²) recursions. Forward answers how likely is this sequence by carrying one column of numbers through time instead of re-walking shared prefixes; Viterbi answers which hidden path explains it by swapping the sum for a max and keeping backpointers; forward-backward answers what was the state at time t by multiplying past and future evidence; and Baum-Welch — EM (the engine behind GMM D22) applied to sequences — learns all three tables from raw observations with no labels whatsoever, its log-likelihood provably never decreasing. The costs are the usual EM ones: local optima that demand random restarts, a state count you must choose yourself, and the strong Markov assumption that a single current state summarises the entire past. 👉 When your data is a sequence, the thing you actually care about is hidden, and you want latent states that mean something rather than a black box, reach for the HMM.
