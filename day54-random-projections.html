MachineLearningFromZero · Day 54

🎲 Random Projections — the almost-magical result that you can slash a dataset from thousands of dimensions down to a few dozen by multiplying it with a matrix of random numbers, and the geometry survives. No looking at the data, no eigenvectors, no training — just draw a random linear map R and send every point x to (1/√k)·R·x. The Johnson–Lindenstrauss lemma promises that for any set of n points there exists such a map into k ≈ O(log n / ε²) dimensions that preserves every pairwise distance within a factor of (1 ± ε) — and the astonishing part is that k depends only on how many points you have and how much distortion you'll tolerate, not on the original dimension D at all. A 10,000-dimensional bag-of-words and a 1,000,000-dimensional one collapse to the same target size. Why does a random direction preserve length? Because the squared length of a projected vector is a sum of k independent, identically-distributed contributions with mean equal to the true squared length — so by concentration of measure it clusters tightly around the truth, and the more directions k you keep the tighter it clusters. Everything below runs live in your browser: real points scattered in high-D, a random Gaussian (or sparse ±1 Achlioptas) matrix built by hand, and a scatter of original distance vs projected distance that hugs the diagonal — with a live distortion histogram tightening and a k slider driving the error down like 1/√k.

You can compress data without ever looking at it. Multiply your points by a matrix of random numbers, keep only k of the output coordinates, and — provably — the distances between points barely change. That is random projection, and its licence is the Johnson–Lindenstrauss lemma: any n points in any number of dimensions can be mapped into k ≈ O(log n / ε²) dimensions so that every pairwise distance is preserved to within (1 ± ε). The projected squared length of a vector is an average of k independent random contributions, each with the right mean, so it concentrates on the true value — and averaging more of them (bigger k) makes the estimate tighter. 🔨 Build it yourself

    
Random projection is one of the shortest dimensionality-reduction algorithms there is — the exact routine the LOOK tab runs, no scikit-learn black box. Below is the runnable core: the random Gaussian matrix, the one-line projection, the sparse ±1 (Achlioptas) variant that skips two-thirds of the multiplies, the distortion measurement, the Johnson–Lindenstrauss dimension formula, and the standard tools. Every dot the LOOK tab draws comes from these snippets.

    
    
      
  1. 
        
    1
    The random Gaussian matrix
    
        
    The entire "model" is a k × D matrix of independent standard-normal numbers, scaled by 1/√k. Nothing about your data is ever consulted — the map is chosen before the data is seen. The 1/√k factor is the calibration that makes the projection preserve lengths in expectation rather than inflating them by a factor of √k.
    
        
    // standard normal via Box–Muller
function randn(rng) {
  let u = 0, v = 0;
  while (u === 0) u = rng();
  while (v === 0) v = rng();
  return Math.sqrt(-2 * Math.log(u)) * Math.cos(2 * Math.PI * v);
}
// k×D Gaussian projection matrix, row-major, scaled 1/√k
function gaussianMatrix(k, D, rng) {
  const R = new Float64Array(k * D);
  const s = 1 / Math.sqrt(k);
  for (let i = 0; i < k * D; i++) R[i] = s * randn(rng);
  return R;                          // E‖Rx‖² = ‖x‖²
}

  2. 
        
    2
    The projection — one matrix–vector product
    
        
    Reducing a point from D dimensions to k is a single matrix–vector multiply: coordinate r of the output is the dot product of row r of R with the point. That is it — no iteration, no fitting, no eigen-decomposition. For a whole dataset it is one (N×D)·(D×k) matrix product.
    
        
    // project N points (flat N*D) down to N*k
function project(X, N, D, R, k) {
  const Y = new Float64Array(N * k);
  for (let n = 0; n < N; n++)
    for (let r = 0; r < k; r++) {
      let acc = 0;
      for (let d = 0; d < D; d++) acc += R[r * D + d] * X[n * D + d];
      Y[n * k + r] = acc;            // yₙᵣ = rowᵣ · xₙ
    }
  return Y;
}

    The sparse ±1 variant (Achlioptas)
    
        
    You do not need real-valued Gaussians. Achlioptas showed that entries drawn as √3 × {+1 with prob 1/6, 0 with prob 2/3, −1 with prob 1/6} give the same JL guarantee — yet two-thirds of the entries are zero (so you skip those multiplies) and the rest are just additions and subtractions. It is faster, database-friendly, and needs no floating-point RNG. The LOOK tab's "sparse ±1" toggle uses exactly this.
    
        
    // Achlioptas sparse ±1 matrix, scaled 1/√k
function sparseMatrix(k, D, rng) {
  const R = new Float64Array(k * D);
  const s = Math.sqrt(3 / k);        // √3 · (1/√k)
  for (let i = 0; i < k * D; i++) {
    const u = rng();
    R[i] = u < 1/6 ? s : (u < 1/3 ? -s : 0);   // ⅔ are zeros
  }
  return R;
}

    Measuring the distortion
    
        
    To check the promise you compare every pairwise distance before and after. The ratio ‖yᵢ−yⱼ‖ / ‖xᵢ−xⱼ‖ should sit near 1; its spread is the distortion. This is precisely what fills the scatter and the histogram — a mean ratio near 1.0 and an RMS distortion that shrinks like 1/√k.
    
        
    function distortionStats(X, Y, N, D, k) {
  let sum = 0, sumSq = 0, worst = 0, m = 0;
  const dist = (A, i, j, dim) => {
    let s = 0; for (let d = 0; d < dim; d++) { const t = A[i*dim+d]-A[j*dim+d]; s += t*t; }
    return Math.sqrt(s);
  };
  for (let i = 0; i < N; i++) for (let j = i + 1; j < N; j++) {
    const o = dist(X, i, j, D); if (o < 1e-9) continue;
    const r = dist(Y, i, j, k) / o;              // distance ratio
    sum += r; sumSq += (r-1)*(r-1); worst = Math.max(worst, Math.abs(r-1)); m++;
  }
  return { mean: sum/m, rms: Math.sqrt(sumSq/m), worst };
}

    How many dimensions? The JL formula
    
        
    The Johnson–Lindenstrauss lemma pins the target dimension: to preserve all n(n−1)/2 pairwise distances within (1 ± ε) with high probability, k ≳ (4 ln n)/(ε²/2 − ε³/3), i.e. O(log n / ε²). The single most important feature of this expression is what is absent from it: the original dimension D. Ten thousand features or ten million, the target k is the same.
    
        
    # scikit-learn's exact bound (the constant matters)
import numpy as np
def jl_min_dim(n, eps):
    return int(np.ceil((4 * np.log(n)) / (eps**2/2 - eps**3/3)))

jl_min_dim(1_000_000, 0.1)   # ~ 15,000  — independent of D
jl_min_dim(1_000_000, 0.3)   # ~ 1,700
# note: worst-case & loose; typical distortion is far smaller

    In practice — the standard tools
    
        
    You rarely hand-roll it. scikit-learn ships GaussianRandomProjection and the faster SparseRandomProjection, and johnson_lindenstrauss_min_dim to size k; passing n_components='auto' lets it pick k from your sample count and a target eps. Random projection is a favourite front-end for speeding up kNN, clustering, and locality-sensitive hashing on very high-dimensional data.
    
        
    # scikit-learn — random projection in three lines
from sklearn.random_projection import (
    SparseRandomProjection, johnson_lindenstrauss_min_dim)

k = johnson_lindenstrauss_min_dim(n_samples=10_000, eps=0.2)
rp = SparseRandomProjection(n_components=k, random_state=0)
X_small = rp.fit_transform(X)        # fit ignores X's values — just its shape

The trade is how much you're willing to look at the data, and what you need to preserve. PCA (Day 14) is optimal for keeping variance in a linear subspace but must compute an SVD of your data — data-dependent and O(D²) or worse. Random projection makes the opposite bet: don't look at the data at all, just multiply by random noise; you lose PCA's optimality but gain a distance-preserving guarantee, a target size that ignores D entirely, and a single blazing matmul — which is why it is the go-to preprocessor for kNN, k-means, and locality-sensitive hashing on millions of features. t-SNE / UMAP (Days 23–24) preserve local neighbourhoods for visualisation but distort distances and don't scale as a general reducer. Autoencoders learn a task-shaped nonlinear code but need training and lots of data. Feature selection keeps original, interpretable columns. Random projection's genius is buying a provable, dimension-independent distance guarantee with nothing more than a matrix of random numbers — the same reason it degrades gracefully: pick k too small and distances just blur, they never break.

    


    
🎉 Day 54 of MachineLearningFromZero done — compressing data with pure randomness.
Random projection reduces dimensions by the most audacious trick imaginable: multiply your points by a matrix of random numbers — Gaussian, or a sparse ±1 Achlioptas matrix that zeros two-thirds of its entries — scale by 1/√k, and keep the output. The Johnson–Lindenstrauss lemma guarantees that k ≈ O(log n / ε²) dimensions preserve every pairwise distance within (1 ± ε), and — the miracle — that k depends only on the number of points and your tolerance, never on the original dimension D. It works because a projected squared distance is an average of k independent, correctly-centred contributions, so by concentration of measure it clusters ever more tightly around the truth as k grows — the distortion falling like 1/√k. No SVD, no training, no data-peeking, no iteration: a single matrix multiply. That places it against the data-dependent reducers — PCA (Day 14) and t-SNE / UMAP (Days 23–24) — as the fast, oblivious, distance-preserving alternative, beloved for kNN, clustering, and LSH on enormous feature spaces. 👉 When D is huge, you need speed, and pairwise distances are what matter, reach for a random projection.
