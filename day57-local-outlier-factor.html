MachineLearningFromZero · Day 57

🔦 The Local Outlier Factor (LOF) — outlier detection that refuses to use a single global ruler. Every distance-based flag before it (and the Elliptic Envelope (D56)) asks one global question — "how far is this point from the bulk?" — and that question breaks the moment your data has regions of different density: a point sitting a perfectly normal distance from its neighbours inside a loose cluster looks, to a global cutoff, exactly like a genuine anomaly hovering just outside a tight one. LOF's whole idea is to make the comparison local: score each point by how its own neighbourhood density compares to the density of its neighbours' neighbourhoods. Concretely it builds up four quantities by hand — the k-distance (distance to the k-th nearest neighbour, which sets a per-point notion of "near"), the reachability distance reach-distk(A,B) = max(k-distance(B), d(A,B)) (a smoothing trick that stops a point's density estimate from spiking when it happens to fall right on top of a neighbour), the local reachability density lrdk(A) = 1 / meanB∈Nk reach-distk(A,B) (inverse average reach-distance — big when the point is crowded, small when it's lonely), and finally the score itself, the ratio LOFk(A) = meanB∈Nk lrdk(B) / lrdk(A) — how much denser are my neighbours than I am? The payoff is a calibrated, self-normalising number: LOF ≈ 1 means "just as dense as my crowd" (inlier), LOF ≫ 1 means "my neighbours live in a far denser place than I do" (a local outlier), and LOF < 1 means you're in a denser pocket than your neighbours. Because the reference is always the local crowd, LOF flags a point that is anomalous relative to its own cluster's density even when it isn't globally far at all — the exact case a global distance threshold or the one-ellipse D56 model gets wrong. Everything below runs live in your browser: clusters of deliberately different density you can add points to, hand-rolled kNN / k-distance / reachability / lrd / the LOF ratio, the k-neighbour links drawn on hover, a k slider whose choice visibly changes the scores, and a head-to-head against a global distance cutoff that false-alarms on the sparse cluster and misses the dense-fringe outlier LOF catches. It is the density-ratio, shape-free member of the outlier-detection family alongside Isolation Forest (D26) and the Elliptic Envelope (D56).

Score every point by how its local density compares to its neighbours'. Find each point's k nearest neighbours, measure how crowded it is with the local reachability density lrd, then divide the average lrd of its neighbours by its own. That ratio is the LOF score: ≈1 means "as dense as my crowd" (inlier), ≫1 means "my neighbours live somewhere far denser than I do" (a local outlier). Because the yardstick is always the local crowd, LOF flags a point that is abnormal for its cluster even when a global distance ruler — or a single fitted ellipse — would wave it through. Every quantity below — k-distance, reachability distance, lrd, and the LOF ratio — is built from scratch, live, on clusters of different density and points you place yourself.

🔨 Build it yourself

    
LOF is a stack of four small ideas, each a few lines — the exact routine the LOOK tab runs, no scikit-learn black box. Below is the runnable core: brute-force kNN and the k-distance neighbourhood (with ties), the reachability distance that smooths density estimates, the local reachability density lrd, the LOF ratio that compares a point to its neighbours, and the one driver that returns every quantity the LOOK tab draws. It is O(n²) here for clarity; production LOF uses a KD-/ball-tree for the neighbour search.

    
    
      
  1. 
        
    1
    Distances and brute-force kNN
    
        
    Everything starts with, for each point, the sorted list of every other point by distance. Plain Euclidean here. This O(n²) loop is fine for a few hundred points; libraries swap in a spatial tree, but the LOF quantities on top are identical.
    
        
    // euclidean distance in normalised [0,1] coordinates
function dist(a, b) { return Math.hypot(a.x - b.x, a.y - b.y); }

// for each point i, all other points sorted nearest-first: [{ j, d }, ...]
function knnAll(pts) {
  const n = pts.length, nbrs = [];
  for (let i = 0; i < n; i++) {
    const ds = [];
    for (let j = 0; j < n; j++) if (j !== i) ds.push({ j, d: dist(pts[i], pts[j]) });
    ds.sort((a, b) => a.d - b.d);   // nearest first
    nbrs.push(ds);
  }
  return nbrs;
}
    
      
    2. 
      
  2. 
        
    2
    k-distance and the k-distance neighbourhood
    
        
    The k-distance of a point is the distance to its k-th nearest neighbour — a per-point notion of "how far is near here". The k-distance neighbourhood Nk is every point at most that far away; it can hold more than k points if several tie at the boundary, which is exactly the definition Breunig et al. use.
    
        
    // k-distance = distance to the k-th neighbour (index k-1 in the sorted list)
function kDistance(nbrsRow, k) {
  const kk = Math.min(k, nbrsRow.length);
  return nbrsRow[kk - 1].d;
}
// N_k = all neighbours within the k-distance (ties at the edge are included)
function kNeighbourhood(nbrsRow, kdist) {
  const out = [];
  for (const o of nbrsRow) { if (o.d <= kdist + 1e-12) out.push(o.j); else break; }
  return out;
}
    
      
    3. 
      
  3. 
        
    3
    Reachability distance — the smoothing trick
    
        
    The reachability distance of A from B is max(k-distance(B), d(A,B)). If A is well inside B's neighbourhood the raw distance is replaced by B's k-distance — a floor. This stops the density estimate from exploding when two points happen to sit almost on top of each other, and makes lrd vary smoothly. It is deliberately asymmetric: reach(A,B) ≠ reach(B,A) in general.
    
        
    // reach-dist_k(A, B) = max( k-distance(B), d(A,B) )   — floored by B's k-distance
function reachDist(i, j, pts, kdist) {
  return Math.max(kdist[j], dist(pts[i], pts[j]));
}
// note the floor: if A is closer to B than B's own k-distance,
// we PRETEND it's exactly k-distance(B). This smooths lrd.
    
      
    4. 
      
  4. 
        
    4
    Local reachability density (lrd)
    
        
    A point's density is the inverse of its average reachability distance to its neighbourhood: lrd(A) = 1 / meanB∈Nk reach-dist(A,B). Small average reach-distance ⇒ crowded ⇒ high lrd; big average ⇒ lonely ⇒ low lrd. This is an absolute local density; the LOF ratio in the next step is what makes it comparable across regions of different density.
    
        
    // lrd(i) = 1 / average reach-dist from i to each point in its neighbourhood
function localReachDensity(i, Nk, pts, kdist) {
  const nb = Nk[i];
  let s = 0;
  for (const j of nb) s += reachDist(i, j, pts, kdist);
  const avg = s / Math.max(1, nb.length);
  return avg > 1e-12 ? 1 / avg : 1e12;   // crowded → big, lonely → small
}
    
      
    5. 
      
  5. 
        
    5
    The LOF ratio — density relative to your neighbours
    
        
    The score itself: divide the average lrd of your neighbours by your own lrd. LOF ≈ 1 means you're as dense as the crowd around you (inlier). LOF ≫ 1 means your neighbours live somewhere far denser than you do — you are a local outlier. LOF < 1 means you're in a denser pocket than your neighbours. This ratio is the whole point: it self-normalises, so a loose cluster and a tight cluster both score ≈ 1 internally, and only the genuinely-anomalous-for-their-region points spike.
    
        
    // LOF(i) = mean( lrd(neighbour) ) / lrd(i)
function lofScore(i, Nk, lrd) {
  const nb = Nk[i];
  let s = 0;
  for (const j of nb) s += lrd[j];
  const meanNbLrd = s / Math.max(1, nb.length);
  return meanNbLrd / (lrd[i] > 1e-12 ? lrd[i] : 1e-12);
}
// ≈1 inlier · ≫1 local outlier · <1 in a denser pocket than the neighbours
    
      
    6. 
      
  6. 
        
    6
    Putting it together — score every point
    
        
    One driver: neighbours → k-distances → neighbourhoods → every lrd → every LOF. Order matters — all k-distances must exist before any reachability distance, and all lrds before any ratio. This one function feeds all three LOOK demos.
    
        
    function computeLOF(pts, k) {
  const n = pts.length;
  k = Math.max(1, Math.min(k, n - 1));
  const nbrs  = knnAll(pts);
  const kdist = nbrs.map(row => kDistance(row, k));                 // step 2
  const Nk    = nbrs.map((row, i) => kNeighbourhood(row, kdist[i]));// step 2
  const lrd   = pts.map((_, i) => localReachDensity(i, Nk, pts, kdist)); // steps 3–4
  const lof   = pts.map((_, i) => lofScore(i, Nk, lrd));           // step 5
  return { nbrs, kdist, Nk, lrd, lof, k };
}
// sanity: a point deep inside either cluster → LOF ≈ 1 (NaN-free);
// a dense-cluster fringe point → LOF > 1 even though it isn't globally far;
// a lone point far from everything → the largest LOF of all.

  7. 
        
    7
    In practice — the standard tool
    
        
    You rarely hand-roll it. scikit-learn ships LocalOutlierFactor, which does exactly this with a spatial tree for the neighbour search. Note it is transductive by default — fit_predict scores the training set and there is no predict unless you set novelty=True. The single most important knob is n_neighbors (k): too small and it chases noise, too large and it blurs local structure back toward a global method.
    
        
    # scikit-learn — local outlier factor in three lines
from sklearn.neighbors import LocalOutlierFactor

lof = LocalOutlierFactor(n_neighbors=20, contamination="auto")
labels = lof.fit_predict(X)          # +1 inlier, −1 outlier (transductive)
scores = -lof.negative_outlier_factor_   # the LOF value; ~1 inlier, ≫1 outlier

LOF is the density-ratio, fully-local corner of outlier detection: it makes no shape assumption and, crucially, no uniform-density assumption — the exact blind spot of the Elliptic Envelope (Day 56), whose single fitted ellipse assumes one global scale of "normal spread." Where D56 buys a calibrated χ² cutoff by committing to one Gaussian, LOF trades that tidy statistical guarantee for the flexibility to handle clusters of different density and to flag a point that is anomalous only relative to its own neighbourhood. It is the natural companion to Isolation Forest (Day 26) — both are shape-free anomaly scorers — but LOF's reference frame is strictly local, which is its superpower on varying-density data and its weakness in high dimensions, where all distances blur (the curse of dimensionality, Day 46) and the density ratio loses contrast. Its one real knob is k: too small chases sampling noise, too large drags the "local" comparison back toward the global one it was built to escape.

    


    
🎉 Day 57 of MachineLearningFromZero done — an outlier score that asks "denser than me?" of your neighbours, not of the whole dataset.
The Local Outlier Factor abandons the single global distance ruler that every earlier distance method — and the one-ellipse Elliptic Envelope (D56) — relies on, because that ruler breaks the instant your data has regions of different density. Instead it scores each point locally: find its k nearest neighbours, set a per-point k-distance, floor the raw distances into reachability distances max(k-dist(B), d(A,B)) to keep the estimate smooth, invert the average into a local reachability density lrd, and finally take the ratio LOF = mean(neighbour lrd) / lrd. That ratio self-normalises so both a tight and a loose cluster read ≈ 1 inside, and only points that are genuinely sparse for their own region spike to ≫ 1 — catching a dense-cluster fringe point a global cutoff waves through, and sparing a loose-cluster point a global cutoff would wrongly condemn. It joins Isolation Forest (D26) and the Elliptic Envelope (D56) as the shape-free, density-ratio member of the outlier-detection toolbox. 👉 When your "normal" data has clusters of differing density and you care about anomalies relative to the local crowd, reach for LOF — and tune k.
